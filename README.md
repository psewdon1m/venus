# VENUS

Реализация P01: [developer guide и точные команды](.docs/DEVELOPER_GUIDE.md), [текущий статус этапов](.docs/implementation/status.md). Комнаты, игры и публичный вход реализуются на следующих этапах.

**Venus** — многопользовательское пространство для общения, совместного времени и постепенного сближения людей. В одной комнате до **8 отдельных онлайн-участников** могут смотреть общий экран со звуком, слушать синхронизированную музыку, играть в карточные игры, а в следующей фазе — разговаривать по видеосвязи. Комнаты подходят и для удалённой встречи, и для физической компании, собравшейся в одном месте.

> Продуктовая цель: помогать людям легче и безопаснее общаться, раскрывать себя и развивать дружеские и романтические отношения. Развлечения — средство, не самоцель.

**Статус репозитория:** документационный стартовый пакет; НЕ утверждение, что приложение написано, протестировано или развёрнуто. Дата спецификации: **2026-10-18**. Рабочее имя и технические версии компонентов могут уточняться через ADR; изменения фиксируются, а не вносятся молча.

## 2. Непересматриваемая продуктовая рамка v0.1

- **Одна комната, несколько параллельных функций:** cinema + future calls; music + games; без пересоздания комнаты между занятиями.
- **До восьми удалённо подключённых устройств/участников в одной комнате.** Размер состава карточной игры — 2–8.
- **Формат комнаты:** `online` (люди физически раздельно) либо `in_person` (люди собрались вместе; каждому доступно своё устройство с интернетом).
- **Языки индивидуальны:** `ru`, `en`, `tr` для интерфейса и каждой игровой карточки; язык комнаты не существует как общий переключатель.
- **Музыка общая:** выбирает/переключает/останавливает владелец комнаты; состояние синхронизируется; громкость локальная. При `in_person` нужен единый общий динамик во избежание эха; индивидуальная громкость возможна при личном аудиовыводе/наушниках.
- **Кино:** трансляция конкретно захваченной вкладки/экрана и её разрешённого звука (не открытие сайта на каждом клиенте). Управляет трансляцией владелец. DRM и запреты захвата не обходятся.
- **Игры:** Questions / Truth or Dare / Yes, But…; на каждый режим >=100 прошедших редакционную проверку карточек до публичного релиза; независимые раунды и сохраняющиеся между сессиями настройки.
- **Relationship Engine:** индивидуальные направленные отношения, один комфорт-ползунок на участника, нарастающая глубина сессии, контекст online/in_person, предложенные публичные и настоящие приватные парные моменты — всегда с правом отказа.
- **Снимок игровой сессии:** после старта игровые настройки фиксированы; согласие на действие не фиксируется заранее и может быть отозвано всегда.
- **Общий серверный Nginx:** Venus НЕ устанавливает второй Nginx и не управляет глобальным ingress.

## 3. Этапы поставки

1. **G0 — Contracts & design:** утверждение документации, JSON Schema, машинных тестов правил отношений, контент-образцов.
2. **G1 — Rooms & Games:** комнаты 8 человек, приватные настройки, два контекста встречи, локализация RU/EN/TR, 3 режима игр и полный Relationship Engine.
3. **G2 — Music:** лицензированный каталог, синхронное воспроизведение, local volume, in-person single-output, совместимость с играми.
4. **G3 — Cinema Web:** захват вкладки на поддерживаемом desktop, звук + картинка через WebRTC/SFU и диагностика A/V.
5. **G4 — Mobile publishing:** Android/iOS native capture и аудио после независимой проверки на реальных устройствах. Нельзя маркировать как готовое по наличию UI.
6. **G5 — Calls:** видеозвонки и совмещение их с Cinema; не входят в первую реализацию.

G1/G2/G3 допускают параллельную разработку с независимыми контрактами, но не подменяют готовность G0. Нумерация обозначает acceptance gates, а не обещание дат.

Порядок исполнения, зависимости, доказательства переходов и процедуры отката: [поэтапный план реализации P00–P11](.docs/10_IMPLEMENTATION_PLAN.md).

Рабочий комплект P00: [реестры, контракты и тесты](.docs/implementation/README.md), [статус](.docs/implementation/status.md), [решения владельца](.docs/implementation/USER_DECISIONS.md). Подготовка комплекта не означает принятия G0 или готовности приложения.

## 4. Как работать с файлами

1. Прочитайте [порядок авторитетов](.docs/README.md#4-порядок-авторитетов-и-конфликты).
2. Для изменений интерфейса сверяйте UI ↔ визуальный документ ↔ RU/EN/TR.
3. Для изменений игровых правил сверяйте Relationship Engine ↔ карточный контракт ↔ валидатор ↔ регрессионные сценарии.
4. Для релиза сверяйте CI ↔ Part 04/05/12 ↔ deployment readiness и подписанный immutable digest.
5. Любое отклонение от принятого контракта — ADR/issue + тест + версия контракта; не заменяйте факт работающего функционала макетом.

### Локальная проверка образцов карточек

```sh
python -m pip install -r tools/requirements.txt
python tools/validate_cards.py .docs/examples/cards
python -m unittest discover -s tools -p 'test_*.py' -v
python tools/verify_manifest.py
python tools/check_relationship_policy.py
python tools/check_docs.py
```

Команды **валидируют только документационный комплект и образцы**, а не проверяют готовность приложения или права на музыку. Комплект содержит **примеры**, а не 300 production-карточек.

## 5. Правила безопасного использования

Venus не раскрывает список crush/not a friend другим участникам и не интерпретирует Relationship Engine как согласие. Отказ, пропуск, остановка раунда и отказ от пары доступны независимо от игровых настроек. Запрещены обход DRM, запись чужой трансляции по умолчанию, нелицензированная публичная музыкальная библиотека и скрытая пересылка интимных данных в аналитику.

## 6. Незакрытые решения / исследовательские ворота

Техническая поддержка desktop-источников браузерами, аудиозахват Android/iOS, реальная нагрузочная способность VPS, права на каталог и жизненный цикл профилей после полного закрытия комнаты требуют подтверждения. Подробный статус — `.docs/README.md` и `.docs/07_KNOWN_AND_EXPECTED_PROBLEMS.md`.
