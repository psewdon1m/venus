# ADR-034 — OCI/config digest и локальный Docker ID

Статус: IMPLEMENTATION_PENDING_TESTS_AND_INDEPENDENT_REVIEW. Scope: P06 standalone local pilot. До первого qualified release обнаружено: Docker classic и containerd image store могут возвращать разные `image inspect.Id` для одного опубликованного OCI image. У публичного preview inspect.Id равен OCI manifest digest, а build metadata содержит отдельный digest config blob. Использование config digest как единственного локального Docker ID блокирует установку и восстановление.

Wire format `VENUS-RELEASE-1` и исходная schema сохраняются. Подписанный `image.oci_digest` идентифицирует manifest; `image.config_digest` — реальные байты config blob. Release inputs берут config digest из metadata того же build, а не из engine-local Id. При online acquisition обязательны точный RepoDigest, допустимый локальный ID (config либо OCI manifest), labels source/version. Если ID не равен config digest, config blob читается из bounded Docker-save archive, его SHA-256 и labels проверяются перед привязкой локального ID. Layers не извлекаются и целиком не буферизуются.

Локальная owner-only привязка хранит OCI reference, config digest и проверенный native ID. Установка/start обращаются к проверенному native ID. Offline previous archive остаётся fsynced и хешированным; receipt дополнительно связан с подписанными OCI/config. Load без registry проверяет hash архива, config blob и labels, затем native ID. Consumer/operator не получают доступ к mapping, Docker или ключам. Для classic store проверенный config ID остаётся допустимым, включая offline restore без RepoDigest alias.

Исторические fixture proofs, контракты и snapshots не переписываются. Ранее image.Id-совпадение доказывало только однородный engine; оно не доказывало переносимость опубликованного image. Настоящих выпущенных Venus service manifests ещё нет, миграция опубликованных релизов не требуется. Preview0.0.0 остаётся unsigned и не становится installable qualified release.

Гейт: unit negatives для archive/config/labels/identity, настоящий Docker update/offline recovery и exact published service-image install, два независимых review. До этого прежний pre-sign04 остаётся историческим, новый source требует pre-sign05. Откат: вернуть предыдущий executor только до новых мутаций либо восстановить совместимый предыдущий image/DB и protected metadata; не менять immutable registry digest/tag и не откатывать ledgers. P07 не начинается.
