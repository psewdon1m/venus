# ADR-014 · P02 room scope, persistence и admission

Дата: 2026-10-18. Статус: IMPLEMENTING_PENDING_INDEPENDENT_GATE. Владелец: Engineering / Codex. Рубеж: EXIT-P02. Основание: ADR-010/011, U-001…004, автономное поручение владельца.

Room host — consumer capability своей комнаты, не browser operator центральной системы. Guest session не даёт доступ к update/backup/log export/agent administration. Operator surface отсутствует до P06; применимость центральных норм фиксируется отдельным входным review, без изменения upstream snapshots.

SQL migrations versioned, checksum validated, transaction + advisory lock. Room admission/mutations сериализуются row lock; active+reserved slots ограничены уникальным slot1…8. Оpaque256-bit session/invite/ticket verifier хранится hash, host membership создан сервером; cookie room-scoped HttpOnly/Secure/SameSite=Strict. Origin+double-submit CSRF и server-side admission rate limits; WebSocket ticket одноразовый,60s, auth первым frame, без query-token.

AES-256-GCM preferences с versioned внешним keyring, уникальным nonce и AAD room/member/schema; ключ не в БД/образе/backup. Outbox содержит только безопасные projections/references. Presence20/45s, slot reservation90s, host grace10min без перевыборов; room idle24h, primary delete<=24h после close, backup expiry<=7d. Проверка текущего membership/room state обязательна до replay и каждой доставки.

Утверждённой оферты сейчас нет: public entry запрещён. Synthetic fixture разрешён только для изолированных тестов, не объявляет настоящий документ утверждённым. Public legal/entry readiness — P05 prerequisite. Lifecycle/revisions/retention и fail-closed policy проверяются на PostgreSQL и HTTP/WS, не только schema tests.

После независимого review plaintext SHA для low-entropy preference requests запрещён: idempotency fingerprint — domain-separated HMAC внешним versioned keyring; проверка replay использует сохранённую key version, старые ключи сохраняются до удаления соответствующих записей/backup. Preferences и все idempotent replies используют authenticated padded-json-v1 envelope фиксированных16384 bytes, включая случайный padding и защищённую длину JSON. Это убирает dictionary/hash и ciphertext-length oracle для comfort/edges; nonce/version/record existence/readiness остаются metadata. Отдельный bulk DB backup использует json-v1 и шифруется целиком; privacy-bearing строки внутри него уже padded. Смена формата до первого P02 deployment допускается только в unreleased migration001; после приёмки checksum менять нельзя.

Audit metadata (room UUID, actor UUID или system/null, allowlisted action, server request UUID, timestamp) фиксируется в той же транзакции, без body/comfort/relations/capabilities. Audit и outbox hard-bounded:10000 events/64MiB с serialized insert+prune; audit age30d, outbox age24h. Room-linked строки каскадно удаляются вместе с закрытой комнатой через23h, что приоритетнее общего audit age. Audit failure откатывает изменение. Наличие public safe outbox не подменяет audit.

Meaningful activity: create/join/profile/context/settings/skip/leave. Heartbeat, snapshot, ticket, presence/reconnect/reaccept не продлевают idle24h. Presence45s от heartbeat, reservation90s от connect/ping/disconnect/reserve; expiry при now>=deadline. Host grace10min — только граница ожидания: отсутствуют election и auto-close; бывший host сохраняет identity/role при освобождении slot. Room cookie24h, server session sliding24h при валидном ping и немедленный revoke при leave/close; жизненный цикл комнаты имеет приоритет. Публичное восстановление и key recovery/operator workflows — P06, локальная совместимость и disposable recovery — P02.
