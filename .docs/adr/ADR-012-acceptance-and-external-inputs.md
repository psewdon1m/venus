# ADR-012 · Принятие P00, роли и отложенные критерии

**Дата:** 2026-10-18 · **ревизия:** P00-2 · **статус:** `ACCEPTED`.

**Ответственный профиль:** Product / Engineering / QA / Privacy. **Принимающий:** Владелец проекта (продукт); separate review agents /root/contract_review, /root/evidence_review. **Последний рубеж:** EXIT-P00.

## Контекст и вопрос

Назначить принимающих; подтвердить scope/flow contracts; получить central sources. Нужны будущие fairness/inference/capacity/RPO/RTO профили до измерений.

## Варианты / подготовленное решение

Автор готовит evidence, независимые reviewers принимают гейт. До назначения/принятия P00 IN_REVIEW, G0 NOT_ACCEPTED.

## Доказательства для принятия

U-004/U-005, записанное решение, подписанный/идентифицированный review. Fairness/RPO/RTO имеют отдельные tasks и блокируют P03/P06, не выдумываются численно.

## Последствия, совместимость и откат

Открыть гейт повторно при изменении inputs; прежние отчёты сохранить, source snapshots не редактировать.

## Принятое решение P00-2 · 2026-10-18

Гейты проверяют отдельные агенты с отчётами, привязанными к input hashes. Round1 FAIL сохраняется; исполнитель исправляет; тесты и независимый review повторяются до green. Проверяющий не автор своего проверяемого изменения. External/production/content authorizations не выдумываются.

Основание: U-004 — [прямое решение владельца](../implementation/user-decisions.v1.json). Предыдущие варианты выше сохраняются как история; текущим является этот раздел. Принятие продукта/процесса не утверждает реализованность и не закрывает технический гейт без evidence.

## Технический review P00-2

По принятому U-004 проверку выполняют отдельные агенты с отчётами и input hashes. Round1 содержит FAIL, исправления требуют повторного review; локальные тесты сами не принимают гейт. Актуальный результат хранится в implementation/status.md и bound gate report.
