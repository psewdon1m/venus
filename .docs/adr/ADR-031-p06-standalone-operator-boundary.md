# ADR-031 — собственный операторский контур Venus

Дата: 2026-10-24. Статус: принято инженерное решение до реализации; тесты и независимая приёмка ещё не выполнены. Scope: P06 standalone-local-pilot-v2.

Consumer API остаётся UID1000 без Docker socket, operator token, release private key и доступа к certbot/соседним проектам. Отдельный operator HTTP/UI процесс UID1002 доступен только на host loopback4310, использует отдельный bearer credential без browser storage и exact Origin/Host. Room identity не является operator identity.

Исполнитель UID1001 слушает защищённый Unix socket0660 с группой1002. Ему доступен Docker CLI/socket и только собственные конфигурация, журнал, spool и backup directory. Это доверенный узкий компонент, а не недоверенный sandbox: владение Docker socket даёт полномочия daemon. На production нужен выделенный Venus/rootless daemon; локальный Docker Desktop drill использует общий daemon и не доказывает такую production-изоляцию. Web-процесс socket не получает. API исполнителя принимает только release SHA/job UUID и фиксированное действие; никогда shell, path, URL, compose text или произвольные Docker arguments. Docker-команды формируются из установленного шаблона и доверенной локальной конфигурации, чужие контейнеры/volumes запрещены проверкой project labels.

Релизный протокол `VENUS-RELEASE-1` использует Ed25519 и подписывает точные canonical manifest bytes. Public SPKI/key_id закрепляются отдельно, private key никогда не входит в image/bundle/Git. Bundle содержит только проверенный immutable compose template и документацию, не исполняется. Image identity включает OCI manifest digest и runtime config digest. Неограниченная загрузка URL и исполняемый скрипт из архива отсутствуют. Import — локальная административная CLI операция; apply повторно проверяет подпись/размеры/digests/schema/version/environment.

Один устойчивый job UUID, файловый lock и durable журнал фаз запрещают конкурентное применение/повторную мутацию. До остановки A выполняются все stateless проверки и сохраняется offline previous image. Перед mutation A останавливается, serving gate закрывается; создаётся свежий полный PostgreSQL custom-format dump в owner-only host-файле temp→fsync→rename→directory-fsync. Backup manifest фиксирует schema/source/time/digest/size/write boundary. Backup не включает .env, tokens или keyring. Согласованность достигается quiesce всех app writers; external backup-copy не относится к Venus.

Deletion/catalogue ledgers и пять topic chain/witness/birth каталогов находятся на отдельном persistent protected host mount, не входят в откат БД. Durable high-water witness запрещает missing/truncated/regressed global ledgers между рестартами. P06 профиль отключает pruning deletion ledger. Bootstrap/provisioning ledger разрешён только явной initial install, обычный restart не создаёт потерянную авторитетную историю. После restore migrations/reconcile/retirement barriers завершаются до serving. Keys и protected metadata восстанавливаются отдельно, без заявления чистого-host recovery одним DB-файлом.

При fault до mutation остаётся A. После mutation restore согласованного backup+совместимого A выполняется при закрытом serving; protected ledgers сохраняются. Blind image downgrade при schema mismatch запрещён. Неоконченный job требует явного recover/cancel, автоматического restore на обычном restart нет. Исходная ошибка и outcome recovery сохраняются отдельно. RPO/RTO production SLA не утверждены; local recovery profile должен назвать реальную write boundary и post-backup writes.

Совместимость: P05 без новых environment flags сохраняет прежний запуск. Новый standalone install требует serving gate/protected witness; новый manifest не трактуется как контракт внешнего Updater. Исторические контракты/snapshots не изменяются. Откат: закрыть serving, отозвать candidate, вернуть совместимый комплект image/schema/config по принятому backup; не возвращать старые deletion/withdrawal ledgers. Если recovery не доказан, оставить serving закрытым и журнал recovery-failed. P07 не входит в решение.
