# ADR-015 · P03 engine, recovery и протокол измерений

Дата:2026-10-18. Статус: IMPLEMENTING_WITH_ENTRY_OBLIGATIONS / MEASUREMENTS_PENDING. Владелец: Engineering / Privacy / QA. Основание: RE-1 и implementation plan P03; независимый [entry review](../implementation/reviews/p03/entry-review.md). Статистические симуляции ещё не запускались; критерии фиксируются до результатов. Предложенные numeric policy параметры не становятся измеренным результатом сами по себе.

## Identity и hard safety

Server-only engine использует exact immutable RE-1 JSON и его SHA256,36-cell resolver, default friendship explicit=false и comfort0. Никаких locale/name/host-derived selection privileges. Snapshot включает exact player UUIDs, directed edges/comfort, mode/context/count,256-bit seed, policy digest и reviewed pack digest; ciphertext привязан AAD room/session/schema. Snapshot после start не меняется. Неизвестная policy/pack, отсутствие capability или безопасных вариантов дают явную ошибку; draft/rejected/непроверенный pack запрещён. Production reviewed registry отсутствует до P04; isolated tests имеют явно synthetic fixture, не production catalogue.

Приоритет: hard guards сильнее soft targets; в частности private stage>=3 блокирует RE-1 soft stage2 target0.08. Private invitation30s, active budget180s от двух accepts; отдельный action consent30s, не дольше active budget. Accept только своим authenticated UUID и актуальным offer/scope/proposal revision; decline/stop/timeout терминальны для предложения и выигрывают итог гонки. Host не принимает за другого. Online private требует private_text_chat capability; до P05 её нет. Snapshot не расширяется spectator/new-name identity.

## Fairness и inference · prereg P03-M1

Fairness denominator: K — число выбранных pair invitations; D=2K — число отдельных персональных приглашений; share_i=appearances_i/D. При K=0 share=N/A. Для N=2 обе доли0.5 неизбежны; разнообразие партнёров не обещается. Для N=3 ограничение appearances_i/K<=0.5 математически невозможно для всех участников одновременно, поэтому JSON0.5 применяется к individual invitations D, не переопределяет raw pair appearances. В отчёте показываются оба denominator. Anti-repeat и мягкое downweight остаются отдельными guards; при единственной допустимой паре отсутствие альтернатив явно фиксируется.

Preregistered deterministic seed corpus: prefix `venus:P03-M1:train` для отдельных диагностик и `venus:P03-M1:test:<size>:<index>` для финальных10000сессий на каждый размер2…8, всего70000. Финальные seeds не подбираются по результатам; failures сохраняются. Все3режима,2контекста, comfort0…4, шесть directed labels и1…100 rounds входят в corpus/отдельные exhaustive boundary tests. Каждый committed round проверяется по15invariants; безопасный отказ учитывается отдельно и не выдаётся за завершённую игру.

Критерии до измерений:0safety violations;0card repeats в одной сессии; private<=ceil(.25*Nrounds), stage1/2private=0. При допустимых unused alternatives исключается повтор одной private пары подряд. В exchangeable balanced profiles aggregate max−min shares<=0.02; individualshare<=0.5. G/F opportunity frequency на matched eligible pools: ratio>1 с нижней95%CI>1. Публичные сравнения F/G,F/M,G/M при одинаковых observable confounders: held-out classifier AUC с верхней95%CI<=0.65. Metadata/body projections проходят exact forbidden-field checks; уникальный deterministic class decoder блокирует гейт. Нулевой observational/social inference не обещается.

Предлагаемая anti-inference реализация до measurement:95% uniform admissible-pair probability +5% RE-1 numeric pair-weight prior, с downweight по уже committed history. Это сохраняет ненулевую мягкую инициативу G при общей поддержке распределений. Новый mix — technical proposed baseline этого ADR; numeric matrix/guards RE-1 не изменяются. Общий каталог не должен создавать публичный deterministic class/comfort decoder: sensitive class, positive-comfort и physical content требуют scoped private delivery либо отказа pack compatibility. Public common-support cards используют comfort0 и none/acquaintance scope. Область этого conservative surface guard проверяется независимым entry/privacy review до финального допуска.

Обучение classifier и границы CI фиксируются в [machine protocol P03-M1](../implementation/p03-measurement-protocol.json) до первой финальной выборки: diagonal linear discriminant на отдельных train seeds, Mann-Whitney AUC с ties0.5, Hanley–McNeil normal95%CI. Private admission также требует достаточного common friend_or_more/comfort1 pool для всего private budget, чтобы class-specific exhaustion time не декодировал класс; guard не меняет исходные interaction. Если критерий не пройден, сохранить FAIL и исходный protocol+hash; любое изменение алгоритма/порога создаёт следующую revision с новым независимым review. Скрывать неудачу подбором seeds/threshold запрещено. Thresholds — технические допуски для synthetic evaluation, не обещание anonymity реальных встреч.

## Persistence и возврат

Предложен additive engine migration stream с собственной checksummed table/generation и readiness. Accepted core schema1/migration001 не переписывается; неизвестная core/engine generation fail-closed. Новые engine tables имеют FK room cascade и не меняют consumer identity. Перед возвратом к accepted P02 остановить новые game sessions, терминализировать active/paused и отозвать все consents/private delivery, затем запускать старый image. P02 не обслуживает engine: его изменение preferences/context допустимо лишь после такого fencing. Проверка отката обязана сравнить identities/core rows, terminal game rows и отсутствие private delivery; простой health старого image недостаточен.

Policy/pack обновления не пересчитывают старые snapshots; сохраняются pinned versions или сессия безопасно прекращается с явной ошибкой. Restore включает engine rows и точный pack; current deletion ledger/closed-room revoke применяются до serving. Ни старое согласие, ни seed не переносятся в новую игру.
