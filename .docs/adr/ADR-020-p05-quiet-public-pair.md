# ADR-020 · Тихое согласие перед публичным парным раундом

Дата: 2026-10-19. Статус: инженерное решение принято по предоставленной рецензии владельца; реализация и независимая приёмка продолжаются. Основание: `P04-GLOBAL-QUIET-PUBLIC-OPT-IN` / V03 в [рецензии](../implementation/evidence/Venus_P04_FULL_REVIEW_450_2026-10-19.md), [план v2](../10_IMPLEMENTATION_PLAN.md).

## Решение

Новый публичный парный раунд сначала получает приватное нейтральное приглашение обоим выбранным участникам. До двух отдельных подтверждений комната получает только существующий generic round: без card ID, текста задания и списка пары. Каждый участник может тихо отказаться, пропустить или отозвать согласие; причина и автор отказа не публикуются. Таймаут не считается принятием.

Публичное представление и согласие на действие — разные решения. Для показа пары используется invitation offer; если задание требует bilateral action consent, после показа действует отдельный action offer с собственными подтверждениями. Подмена одного другим запрещена. Условия Yes, But… сохраняют собственную proposal revision и сбрасывают прежние подтверждения при изменении.

Используем текущие invitation/response transport shapes и actor-scoped events. Текст приглашения явно объясняет, что после взаимного согласия раунд станет публичным. Нельзя называть его приватным заданием или открывать приватный текстовый чат для `pair_public`. Чат предназначен только для `pair_private` online при функционирующем capability.

## Совместимость

Алгоритм выбора P03, seed, immutable snapshot schema1 и card metadata не меняются этим решением. Дополнительный барьер действует при создании/представлении нового раунда. Старые публичные раунды без invitation сохраняют историческую интерпретацию; включение нового serving требует безопасного завершения несовместимых активных игр. В изолированных старых P03 synthetic factories допускается прежний режим для проверки исторического поведения; основной сервер не предоставляет consumer-переключателя обхода барьера.

Состояние invitation хранится в уже зашифрованном RoundData. HTTP/WS финальный projector проверяет актуальных actors, подтверждения, срок, session/round и membership под существующим dispatch/revoke fence. Если clock или scope недостоверны, публичный показ закрыт. Generic placeholder сам по себе не доказывает защиту: тест должен перехватить фактические HTTP/WS bytes постороннего участника до и после отказа.

## Проверка и откат

Нужны: ни один/один/два accept; тихий decline до показа; отзыв после accept; timeout на границе; подмена пары/offer; outsider/host без actor роли; replay; disconnect и реальное повторное подключение. Проверяются три режима и RU/EN/TR. Сохранение публичного согласия не разрешает приватный prompt/chat.

При дефекте закрыть создание новых Games/остановить затронутую игру и очистить выдачу приглашений. Не переключать живую игру на прежний публичный показ пары без согласия. Исторические тесты и прежние snapshots не переписываются. Старые M3-измерения остаются доказательством своей исходной ревизии и не считаются новой оценкой наблюдаемого P05-протокола.

Текущее состояние: чистый модуль проверки границы добавлен; фактическая интеграция API/WS и Docker negatives должны быть завершены до component PASS. Человеческий HOLD каталога сохраняется независимо от этого ADR.
