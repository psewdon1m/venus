# ADR-027 · Одна точная приватная карточка на сессию

Дата: 2026-10-20. Статус: `IMPLEMENTED_FOCUSED_PASS / INDEPENDENT_AND_ACTUAL_PENDING`.

Нормативный аудит [M3](../implementation/reviews/p05/m3-exact-card-repeat-normative-audit-round01/REPORT.md) подтвердил сохранённый порог ноль повторов точного ID за сессию. Семантическая история приватной пары и этот порог применяются одновременно. Нативная воспроизводящая проверка seed `P05-EXACT-ID-REGRESSION-1`, N8/R100 выявила Q-0108 в раундах55 и78 у разных пар; авторский FAIL сохраняется.

Ревизия `RE-1.P05-TOPIC-3` исключает все уже выбранные/заменённые/отклонённые приватные ID текущей сессии из новых private candidates независимо от пары. Обычная и целевая замена, а также наличие эффективной альтернативной пары используют один фильтр. Restore отвергает повтор точного ID внутри одной session истории. Пустой безопасный результат остаётся пустым, повтор не становится fallback.

Приватная семантическая история между сессиями остаётся ограниченной неупорядоченной парой. Разные ID одной семьи могут быть доступны разным парам. Публичный RNG сохраняет прежний domain `RE-1.P05-TOPIC-2`, не читает приватную историю и не получает дополнительного фильтра; нормативная смена версии не перемешивает публичную последовательность. Private policy `ROOM-TOPIC-2`, recovery, ACL, согласия, сроки, wire schema и SQL не меняются.

Это явная несовместимость engine snapshot2→3: существующий bootGate безопасно прерывает неподдерживаемые активные сессии до выдачи. Старые snapshot/history не переписываются; started prior от несовместимой сессии блокирует новый Start вместо стирания истории. Локальный пилот начинает новые комнаты. Миграция исторических комнат здесь не заявляется.

Откат на engine2 требует запрета новых starts и завершения приватных epochs; хранение истории и отзывов сохраняется. Проверка несовместимости2↔3 отделяется от сильного live-compatible rollback14. Последний проверяет реальное приложение B3 с этим исправлением до нового round-view и A3 с round-view, оба с одинаковой engine3. B3 не объявляется предыдущим production release: это самостоятельная проверяемая промежуточная версия локального кандидата.

Приёмка требует независимого source review, целевых регрессий и фактических Docker проверок. Новое решение владельца для сохранения исходного запрета повторов не требуется.
