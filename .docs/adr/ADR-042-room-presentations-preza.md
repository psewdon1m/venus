# ADR-042 — Preza внутри комнат Venus

Status: implementation contract; supplementary entry review pending.2026-10-25UTC. Authority: U022/U023 room presentations; exact Preza aeca0de85a54ca8c30ff9c7143f9352fdddfdecf and immutable source-audit01/entry-round01. No feature/test/P07 PASS.

Adapt the owner's existing PDF library/render/view/live semantics. Venus room identity replaces Preza public slug/password/admin and SQLite/updater; no external presentation service. Reuse the actual attributed Python render_pdf implementation, with bounded per-page Poppler calls and isolation. No PPTX/editor/animations/source-audio support.

A static same-image converter service has no network/socket/secrets/DB. Exception to entry01's whole-service nonroot proposal: a tiny trusted Python guardian is PID1/root in its own container PID namespace with onlySETUID/SETGID/KILL; untrusted renderer UID/GID65534 has no capabilities. Same-UID daemon/renderer and process-group-only cleanup cannot contain escaped descendants. Guardian refuses PID!=1, kills all other namespace processes before/after each job, reaps them and performs trusted cleanup before acknowledging output or accepting another job. Cleanup failure leaves worker closed; it never proceeds to another room's plaintext. This is a new explicit bounded exception, not a claim of implemented isolation. Supplementary independent entry and actual hostile descendant/permission/resource/quiescence checks are required before acceptance.

Do not change ProtectedAuthority semantics: reuse an independent directory with its atomic+witness/checkpoint pattern and <=256 durable document-ID bindings. Preserve entries when rotating API epoch; never rotate/clear document floors with media leases. Positive content binding changes only at the publish commit point; delete records a permanent retired binding. Saturation fails new imports closed; no silent floor pruning. Old DB restore cannot authorize a retired/replaced generation. Complete encrypted staging permits deterministic rollforward after the protected publish point; a missing/restored-old stage fails closed. Before that point failed replace preserves old content.

Persistent encrypted source/PNG/staging/reservations: global64MiB, room128MiB (global cap dominates); source16MiB,100pages,120DPI,PNG4MiB/page/64MiB independent output ceiling. The effective output allocation is remaining quota minus source/envelope/old active bytes; limits are ceilings, not a promise every combination fits. One active import globally, no need for a queue. Ephemeral spool64MiB+scratch64MiB separately bounded; converter.5CPU/512MiB/32pids, total120s, metadata30s, childCPU90s,stdout+stderr256KiB,geometry8192/8Mpixels,limits set before untrusted work.

Versioned backup2 raises the bounded whole-dump/read/archive/restore ceiling to256MiB only for the new presentation-aware profile; backup1 remains128MiB and readable. New explicit release/profile4 binds static converter/quiescence/asset inclusion; existing signed0.0.1/v2 and media-v3 are immutable. Source/PNG ciphertext lives in PostgreSQL so the operator still saves one backup file on the host; keys/protected witnesses remain outside it. Actual largest-accepted-data restore and conservative whole-DB admission/margin are mandatory, not inferred from pg_database_size. Public dependency/source/license readiness and aggregateP07 remain separate.

Current contract: [PRESENTATIONS.md](../implementation/PRESENTATIONS.md). Rollback first disables/cancels/revokes presentation jobs/read/live and uses a compatible presentation-aware image; preserve additive tables and document floors. Old media-gen3 alone is not an accepted downgrade for this profile. No normal restart automatically restores DB.

Primary isolation basis: [kill(2)](https://man7.org/linux/man-pages/man2/kill.2.html), [PID namespaces](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html). These describe the primitives, not proof that our absent implementation is safe.
