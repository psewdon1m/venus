# P07 — подготовка заключительного локального прогона

Статус: **подготовка, прогон не запущен**. Основание: решение владельца выполнить P08–P11 и презентации раньше общего P07. Этот документ не заменяет выходные гейты плана и не объявляет весь проект принятым.

## Что проверяется перед запуском

- Один чистый commit кандидата, точные lock/toolchain, source inventory и OCI digest. Отдельно сохранить конфигурацию, schema/module generations, pack/catalog digests, версии Docker/Compose и ресурсы хоста.
- Связанные приёмки P05/P06, локальные функциональные P08/P09/P11 и отдельная приёмка презентаций; все замечания их обязательных проверок закрыты. P10 ограничен подготовкой: реальные Android/iOS и нативная поставка остаются HOLD.
- Для презентаций профиль `standalone-local-presentations-v4`, совместимый image/оператор и BK2. Нельзя объявить старый профиль v3 безопасным откатом при включённом модуле. Protected ledgers, media authority и presentation authority не откатываются вместе с БД.
- Отсутствие параллельной очистки Docker и записей агентов в кандидат. Достаточность свободного диска и ресурсов подтверждается до запуска; тестовая инфраструктура изолирована по Compose project.
- До измерений зафиксировать число комнат/клиентов, длительность, churn, пороги и ресурсные ограничения. Базовый proposed soak плана: 60 минут, 8 клиентов, минимум 10 законченных игровых сессий; сокращённый прогон не выдаётся за исполнение этого профиля.

## Матрица заключительного прогона

| Гейт | Обязательный наблюдаемый результат |
|---|---|
| PLAN-P07-REPRO | Сборка/развёртывание из чистого кандидата; точный running digest; повторное создание контейнеров сохраняет согласованные данные без ручного SQL. |
| PLAN-P07-E2E | 8 contexts, отказ девятому, явное 18+, RU/EN/TR, три режима, consent/decline, private chat ACL/TTL, reconnect/restart/finish/replay. Music/Cinema/Calls и презентации проверяются совместно в включённом профиле. |
| PLAN-P07-LOAD | Заранее ограниченная нагрузка, реальные CPU/RAM/storage/egress, admission saturation, disk canary, DB outage, readiness и локальные alerts; вывод применим только к измеренному Docker-хосту. |
| PLAN-P07-RESTORE | Настоящий host backup восстанавливается в отдельную чистую БД; ключи возвращаются отдельно, новые withdrawal/deletion/content bindings действуют до serving. Проверены совместимый previous-image recovery и безопасная остановка первой установки. Независимый агент воспроизводит runbook. |
| PLAN-P07-PILOT | Заранее принятый functional soak с synthetic identities, consent/privacy invariants и реальными числом завершений/длительностью. Друзья считаются участниками только при фактическом тестировании. |

Четыре длинные статистические проверки P03 остаются отдельным ручным набором. Они не добавляются в каждый CI или этот прогон автоматически. Для обнаруженной ошибки: сохранить FAIL и точные inputs, исправить приложение, повторить затронутую проверку; итоговый кандидат должен иметь непротиворечивый source-bound набор доказательств.

## Порядок и остановка

1. Зафиксировать кандидат, профиль, входной отчёт и ограниченные бюджеты; подготовить отдельную среду restore и безопасные synthetic fixtures.
2. Выполнить REPRO/E2E, затем согласованные LOAD/RESTORE/PILOT. В журнале хранить фактические команды, exit codes, исходные ошибки и cleanup. Не публиковать cookies, ключи и частные данные.
3. При отказе закрыть новые admissions/затронутый модуль, сохранить доступный выход и durable состояние. Recovery выполняется по P06 runbook с подтверждённой quiescence всех writers, совместимой схемой и сохранением monotonic authority. Неподтверждённый исход оставляет serving закрытым.
4. После исправлений получить независимые engineering/security gate reports от неавторов. Остановить записи агентов, связать точные tests/reviews/bytes, затем обновить производный manifest и итоговый статус.

## Что этот локальный прогон не доказывает

DNS/TLS/Cloudflare/NAT и реальные устройства, production capacity/SLA, профессиональную языковую/правовую приёмку карточек, права на реальные треки, публикацию нового подписанного media/presentation release. Node/security/dependency findings и P10 blockers закрываются отдельно; синтетический Docker PASS их не устраняет. Домена `venus.shmoza.net` и certbot paths недостаточно для заявления о действующем развёртывании.
