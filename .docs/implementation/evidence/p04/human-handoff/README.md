# P04 · Пакет для реального редакторского ревью

Статус: PENDING_HUMAN_REVIEW. Это задание людям, не согласование, не разрешение публикации и не EXIT-P04.

[450 карточек для чтения](../draft-author-450/REVIEW.md) содержат RU/EN/TR тексты. [Рабочая ведомость](worksheet-450.json) дополнительно содержит полную неизменённую metadata каждой карточки, source path, raw/canonical SHA256 и восемь пустых проверок. В частности, проверять interaction, meeting_contexts, relationship_scope, comfort/stage, consent, physical/going-away, capabilities и safety_tags вместе с текстом. Предыдущий текстовый пакет не заменяет проверку этих полей. Все исходники доступны в `.docs/content/p04/cards`.

От владельца нужны имена/роли независимых редакторов, их языки и подтверждаемая компетенция; авторы черновиков не утверждают себя. Рекомендация: владелец координирует редакционную/rights/safety проверку и назначает компетентных RU, EN и TR рецензентов. Один человек может закрыть только действительно проверенные им направления. За каждой карточкой нужны editorial, safety, ru, en, tr, rights, similarity, diversity; отсутствие romantic/physical не отменяет общий safety review. Для sensitive карточек дополнительно требуется qualified_safety.

Сначала записать замечания и решения по каждой карточке. Проверить оригинальность и права; отсутствие внешнего каталога у агента не подтверждает их. Проверить смысловые повторы, естественность и культурную уместность всех переводов, достаточное разнообразие категорий. Token Jaccard .78 не откалиброван: нулевая очередь не отменяет семантический поиск; нужны размеченные примеры и решение о калибровке. Отдельно оценить уважительный добровольный private сценарий и отсутствие давления на раскрытие личного.

Исправления возвращаются в authoring ledger с сохранением IDs и revision+1; при изменении distributions используется explicit revise CAS. Любое изменение текста или metadata меняет card hash и catalog digest, поэтому старые подписи неприменимы к новому каталогу. Нельзя заменять `needs_review` на `original_verified` вручную.

[Шаблон](unsigned-review-template.json) намеренно невалиден как approval: пустые identity/time/checks/card_hashes/signature и decision=null. После реального ревью человек утверждает только рассмотренный subset и свои компетентные checks, с точными hashes финального каталога. Его Ed25519 private key остаётся у него; в source допускаются только public key и операторское доказательство личности/компетенций. Подпись создаётся над UTF8 canonical JSON самого `review` (рекурсивная сортировка ключей, без пробелов; функция canonical из production engine), не над всей обёрткой. Приватные ключи не отправлять в чат и не коммитить. Проверка подписи не доказывает личность или права сама по себе.

После получения настоящих records используется уже реализованный `build-reviewed` из tools/card-catalog.mjs. Application registry и текущие проверенные source bytes должны пройти новый полный цикл тестов/CI/независимых проверок; этот пакет сам не активирует каталог. Production approved registry сейчас пуст, reviewed=0.

Предел статистических выводов: preregistered P03-M3 использовал свой неизменённый synthetic pack, а не эти450 карточек. Его fairness/GF/inference результаты нельзя переименовать в измерения этого каталога. P04-C2 отдельно проверяет actual eligibility/preflight и private budget на450draft; это не все mixed graphs и не универсальная privacy guarantee. При необходимости новых количественных утверждений о новом pack нужны заранее зафиксированный дополнительный протокол и свежие измерения, с сохранением прежнего M3.
