Прямой запрос владельца — исправить карточки по двум рецензиям 470 r2 параллельно завершению P05. Эта source revision сохраняет исходные контракты, историю и человеческий HOLD. Реализация P05 и его доказательства продолжают относиться к своим прежним входам; новый каталог к ним автоматически не подставляется.

Все 139 ID/revisions/canonical SHA из action list сверены с фактическими JSON. Вводный абзац DELTA содержит 224/141; таблица, приложение из 365 строк и action list согласованно содержат 226/139. Основанием служат точные ID; исходные документы сохранены без исправления этого расхождения.

## Применимость и совместимость

Шесть нейтральных очных карточек Q-1105/1110/1112 и YB-1102/1104/1107, а также онлайн YB-1130 переведены в `pair_public`, `stage=1`, `comfort=0`, `acquaintance`, оба контекста. Двустороннее согласие сохраняется. Тексты больше не обещают приватного разговора. Поздняя стадия и близость больше не требуются для нейтрального сюжета; публикация обращения к паре всё ещё зависит от тихого предварительного согласия в UX.

Другие 48 очных приватных карточек из action list требуют `private_text_chat`; все их тексты явно направляют ответы в чат. Стадия >=3, комфорт >=1, приватная пара, двустороннее согласие, запрет обязательного физического контакта и ухода сохранены. Проверка `required_capabilities` действует в обоих контекстах. Текущий runtime предоставляет этот канал только онлайн: поэтому исправленные очные варианты безопасно не выдаются. Реальная очная доставка не доказана и не включена этой правкой. Разблокировать её можно только после отдельной реализации/проверки доступного обеим сторонам приватного канала; согласие на близость его не заменяет.

Вне 139 остаётся 21 прежняя очная приватная карточка без capability. Их точный список и статус сохранены в отдельном реестре обязательств. Они не менялись этим запросом, и новая ревизия не объявляет весь каталог готовым к приватной выдаче. При будущей интеграции их применимость требует отдельного рассмотрения.

Ответы всех 150 YB теперь имеют одинаковое правило в каждом языке: согласиться, предложить условие или отказаться; новое условие требует свободного согласия второй стороны и явного подтверждения обоих; любой может передумать. Исправлены 26 отличавшихся ответов. Нового интерфейса это правило не создаёт: работоспособность согласования остаётся отдельным обязательством P05.

Категории сохранены сбалансированными: 32 каждой категории для Q/TD, 30 для YB. В отмеченных нейтральных карточках категории «Границы» вместо смены категории сделан явным выбор собственного темпа/пространства/добровольной паузы. TD-1170 получил выбор ощущения и изменение повторяемого момента вместо двух дневниковых описаний; общее чередование похожих механик остаётся задачей selector/UX, а не изменением исторического TopicMap.

Новые пороги и приватный фильтр меняют eligibility и уменьшают прежние приватные пулы. Финальный P04-C2 сохраняет `neutral20=PASS`, но `private_coverage=CONTENT_GAP` в обоих профилях capabilities. Это ожидаемое ограничение исправленного draft, а не пройденный приватный гейт. Новых карточек ради численного покрытия здесь не создавали. Прежние capacity/TopicMap/statistical proofs не применяются к новым хешам; при интеграции нужны новый расчёт и проверка полноты.

## История и откат

В отдельной копии ledger сохранены все 844 исходные ревизии и префикс из 151 события. Добавлены 139 ревизий, 31 `DRAFT_RECORDED` и 3 `REQUEST_REVISED` через существующий API с CAS и проверкой полного batch request. Итог — 983 ревизии /185 событий; 41 batch и 547 резервированных ID неизменны. Исключённые исторические записи не возвращаются в активную выборку 470.

Прежние 470 r2, review450, исключённые 77 ID и перенесённые UX-обязательства не переписываются. Runtime pointer не менялся, поэтому операционный откат не нужен. Для отката draft используется прежний каталог 470 r2 и сохранённый raw ledger; новую ревизию и отчёты не стирают. При будущей интеграции каталог, manifest, TopicMap и все проверки должны быть переключены согласованно на одну точную ревизию.
