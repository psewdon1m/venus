## 2. Условные обозначения и критерий решения

| Код | Значение |
|---|---|
| `KEEP` | Сохранить конкретную редакцию карточки; все общие условия выдачи по-прежнему действуют. |
| `EDIT` | Исправить текст, структуру действия или языковую эквивалентность с сохранением идеи. |
| `RECONTEXT` | Изменить либо дополнить metadata / доступный канал / порог стадии; сама идея допустима. |
| `MOVE_TO_RULES` | Удалить из случайной игровой выдачи; закрепить правило, кнопку или памятку в UX. |
| `REPLACE` | Сохранение текущего смысла нецелесообразно: заменить игровой сюжет/механику. |
| `HOLD` | Не выдавать до переформулирования существенной проблемы. |
| `P0` | Содержательное искажение индивидуального согласия или обещание приватности, способное ввести в заблуждение. |
| `P1` | Существенная системная, контекстная, смысловая или переводческая правка. |
| `P2` | Редакторское улучшение без непосредственного риска согласия. |
| `P3` | Замечаний к локальному тексту не обнаружено; соблюдать общие условия. |

**Оси:** `E` — редактура и игровой смысл; `S` — безопасность, приватность, согласие и применимость; `RU` / `EN` / `TR` — язык и перевод; `IP` — текстовые признаки прав/оригинальности; `SIM` — смысловые повторы; `DIV` — разнообразие механик. В индивидуальных строках указаны **оси, по которым найдено замечание**. `—` означает, что локального замечания по восьми направлениям не выявлено; глобальные замечания ниже применяются также к таким строкам.

Основные риски — публичная адресация, закрытый канал и неверно описанное согласие. | Применять правила из §4, исправить P0 и не путать добровольный диалог с технической защитой переписки. |

## 4. Параметры применения и защита согласия

Эти условия вытекают из содержания карточек и назначения Relationship Engine. Они **не подменяются** наличием в тексте фразы «если оба хотите».

| Контекст карточки | Кому и когда доступна | Канал и согласие |
|---|---|---|
| `G` — `group`, stage 1, comfort 0 | Общий ранний раунд. | Ответ доброволен, пропуск без объяснений. Не выбирать человека из-за его приватных отношений. |
| `S` — `solo`, stage 1, comfort 0 | Личный ход участника. | Право выбрать Truth, Dare или пропуск по правилам режима; устные/жестовые действия нельзя без альтернативы выдавать только текстовым участникам. |
| `PP` — `pair_public`, stage 1, comfort 0 | Публично адресованные P1 и P2, подобранные без раскрытия причин. | До обращения — тихая возможность P2 отказаться; после предложения нового условия отдельно подтвердить согласие **обоих**. |
| `PV-T` — `pair_private`, stage 3, comfort 1 | Только добровольно выбранная пара, оба проходят проверку своего единого глобального уровня комфорта и приватных направленных отношений. | Закрытая устная/текстовая коммуникация; оффлайн можно добровольно отойти, онлайн использовать отдельный приватный канал. |
| `PV-C` — `pair_private`, stage 3, comfort 1 + «только в личном чате» | Такая же пара, но обязательно нужен действующий приватный **текстовый чат** на устройствах обоих участников. | Если чат недоступен — фильтровать, а не показывать невыполнимый сценарий; ответ не передавать в комнату. |

**Разделение трёх независимых факторов:** (1) приватное отношение P1→P2 не равняется отношению P2→P1; (2) глобальный уровень комфорта игрока — один на человека, не на каждую пару; (3) стадия определяет плавную прогрессию, но не повышает согласие и не отменяет право отказаться. При числе игроков до 8 должны быть предотвращены нежелательные повторные назначения одной пары и разглашение мотивов отказа.

**Для `yes_but`** одна и та же строка `responder` повторена в 150/150 карточек на каждом языке — это осознанный пригодный UI-шаблон, не 150 содержательных дублей. После предложения P2 нового условия необходимо новое свободное решение P1, затем явное подтверждение итогового варианта обоими. Право P1 отказаться не выражено в текущем повторяемом тексте.

**Разрыв в шкале:** записей stage 2 нет. Если `stage` означает точную стадию, контент для среднего этапа отсутствует; если это минимальная стадия допуска, этап 2 должен безопасно использовать подходящий ранний пул. Уровни comfort представлены только 0/1; их смысл следует задавать единообразно в модуле выдачи. Нейтральные темы не требуют по содержанию искусственно высокого порога близости.
