# Lifecycle recovery and member-metadata erasure — proposed inactive extension

DESIGNREADY, pending root approval. Existing lifecycle round01 remains exact-source-bound and unchanged. No included functional edits accompany this proposal.

1. Add readonly `retirementStatus(roomId,birth)` under the existing room filesystem lock. It authenticates exact immutable birth and immutable retirement intent; returns a frozen `live` / `retiring` / `retired` classification, with original `retiredAt`/`operationId` only when an intent exists. It works after personal cleanup and, through an authenticated terminal capability, after metadata cleanup. `live` is not an admission/readiness proof.
2. Add an immutable, fixed-size encrypted/authenticated `terminal` file using a separate schema/AAD/MAC domain. Bind protocol2, room, both ledger incarnations, exact taxonomy/policy pins and original closedAt/operationId. No member IDs, topics, prompt/history or owner lists. Proposed additional fields are ciphertext chain/witness hashes+sizes: strict retry can recognize the exact remaining files after one of the two disappears without parsing a missing pair.
3. First terminal publication requires authenticated intent plus independently authenticated lifecycle `room_retired`, both personal files absent, exact birth/pins, validated remaining lifecycle paths/owner/mode/nlink/size, and no unknown/stale filesystem locks. A boolean DB-lock assertion or elapsed time cannot manufacture terminal authority.
4. Publish full terminal bytes, fsync file, atomic rename, fsync directory **before** either lifecycle unlink. On retry, authenticate exact terminal/intent/birth and re-fsync existing terminal+directory before deleting anything. Each remaining file must match the authenticated hash/size; unlink and fsync each directory separately. Partial failure retains authority; unknown/different files deny rather than deleting a foreign object.
5. Refactor cached room context to lazy-open the lifecycle driver. Terminal is checked before opening potentially deleted chain/witness. A valid terminal authorizes status/cleanup retry and denies every normal live/member/wrapper path. Absent terminal never relaxes missing/corrupt required ledger state. Cache observed terminal/intent hashes; disappearance or divergence denies the retained process.
6. Retain birth/intent/terminal room-only metadata for the later P06 bounded prune/backup barrier. Do not implement scanner, recursive delete, terminal prune or crypto erasure. Erasing current service files does not erase keys, external backups, held fds or already delivered data. The caller still owns authenticated same-room DB ordering, time source and retention scheduling.

Counterexamples addressed: crash/rollback losing first retiredAt; killing between the two lifecycle unlinks; a fresh manager trying to parse a missing witness; restoring older live lifecycle files after a terminal marker; a swapped regular same-mode lifecycle file; cleanup requested with only a boolean/age and no durable room retirement. Simultaneous rollback of all independently preserved birth/intent/terminal/witness authorities and trusted floors remains outside the model.
