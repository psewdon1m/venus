## Вход и область решения

Прочитаны текущий v3 overlay плана, ADR-019/009/035, v7/v8 решений. P02/P05 приняты в прежнем local scope; P06 — только Linux classic, известный Desktop export FAIL сохранён. P08 сейчас на targeted tests, его EXIT ещё не принят. По зависимостям P09 не обязан ждать Music, но будущая связка Cinema→pause Music требует проверки фактически включённой P08. U-022 переносит общий P07 после функциональности, не превращает его в PASS. U-024 выбирает local host-file Music; прежнее ожидание выбора источника v7 уже переопределено v8.

Owner contract однозначен: один встроенный SFU того же хоста для Cinema, общих Calls до 8 и приватных пар; отдельной P2P ветки/fallback нет. P11 namespace/consent не принимаются автоматически входным аудитом P09. Host основной комнаты не имеет права входить в чужую пару.

Рекомендован **LiveKit OSS с Venus-owned room-scoped signaling gateway и durable media leases**. Нативный self-host LiveKit без gateway не соответствует обязательному stale-token/rejoin запрету. Это существенное ограничение выбора, а не мелкая настройка TTL.

## Source/security findings

**F01 — обязательный standalone revoke fence.** Self-host сервер не инвалидирует старый JWT при RemoveParticipant/UpdateParticipant. Короткий TTL ограничивает initial join, но не разрывает уже активное media; server refresh выдаёт новые reconnect tokens. Поэтому схема «выдали JWT → RemoveParticipant → больше не выдаём» оставляет окно повторного входа. Cloud revocation не является доступной локальной функцией. [Официальный token lifecycle](https://docs.livekit.io/frontends/reference/tokens-grants/#token-revocation).

**F02 — gateway возможен без изменения SFU source, но ещё не доказан runtime.** Pinned SDK `src/api/utils.ts` сохраняет URL prefix, добавляет `/rtc`, затем `/v1` для нового протокола; validate добавляет `/validate`. SignalClient в обоих вариантах оставляет `access_token` отдельным query field; v1 `join_request` содержит gzip/protobuf настроек/SDP, не заменяет JWT. Сервер `RTCService.SetupRoutes` регистрирует `/rtc`, `/rtc/validate`, `/rtc/v1`, `/rtc/v1/validate`. Нельзя проксировать только старый `/rtc` и объявить весь SDK защищённым. [SDK URL helper](https://github.com/livekit/client-sdk-js/blob/b6b92107809e6df4376003853be5960ba09446e1/src/api/utils.ts), [SignalClient](https://github.com/livekit/client-sdk-js/blob/b6b92107809e6df4376003853be5960ba09446e1/src/api/SignalClient.ts), [RTCService](https://github.com/livekit/livekit/blob/e5655ac20267fa5005dccaf3f0e3bfc3ea688c07/pkg/service/rtcservice.go).

**F03 — нельзя доверять upstream Origin.** LiveKit RTC upgrader CheckOrigin возвращает true, а validate auth middleware допускает wildcard CORS. Venus gateway должен самостоятельно проверять same-origin, room cookie и дубликаты credentials; не наследовать эти upstream допуски. У сервера auth возможен через Authorization Bearer и access_token query — proxy должен запретить неоднозначные/дублированные поля и не давать клиенту подменять внутреннюю авторизацию. JWT/query/SDP и cookies не попадут в access/error logs. [Pinned auth.go](https://github.com/livekit/livekit/blob/e5655ac20267fa5005dccaf3f0e3bfc3ea688c07/pkg/service/auth.go).

**F04 — server removal прекращает media, WS close не заменяет его.** RoomService проверяет roomAdmin и вызывает participant RPC; RoomManager вызывает Room.RemoveParticipant с service-request reason. Room.RemoveParticipant убирает участника и published media/data tracks, далее закрывает participant. Это source evidence пути прекращения, не замер времени/пакетов. API receipt ещё не доказательство отсутствия дальнейших UDP bytes. Нужны targeted media counters после отзыва. [RoomService](https://github.com/livekit/livekit/blob/e5655ac20267fa5005dccaf3f0e3bfc3ea688c07/pkg/service/roomservice.go), [RoomManager](https://github.com/livekit/livekit/blob/e5655ac20267fa5005dccaf3f0e3bfc3ea688c07/pkg/service/roommanager.go), [Room removal](https://github.com/livekit/livekit/blob/e5655ac20267fa5005dccaf3f0e3bfc3ea688c07/pkg/rtc/room.go).

**F05 — аварийная authority/lifetime граница обязательна.** При падении API/gateway уже установленный UDP/DTLS transport способен пережить signaling. Независимый lease watchdog/supervision должен прекращать просроченные/отозванные участники; если remove нельзя подтвердить, quiesce именно Venus media process/namespace ограниченным способом. Без Docker socket у web app и без остановки соседних сервисов. Закрыть proxy и вернуть пользователю «отзыв завершён» при admin API failure нельзя. Механизм и bound принимаются до targeted fault run; здесь они NOT_IMPLEMENTED/NOT_TESTED.

## Обязательный implementation contract

1. **Сеть:** server port7880 только private Docker network, без host published port, прямого HTTP/WS ingress, публичного `/twirp` или универсального reverse proxy. Клиент получает Venus same-origin URL `/api/v1/rooms/:roomId/media/:leaseId/...`, который SDK расширит четырьмя RTC suffix. Proxy strict allowlist этих mapped routes; любые REST/WHIP/SIP/ingress/egress/admin/metrics дополнительные пути закрыты. Для V2 выбрать prefix с реально выдаваемым room cookie, не менять cookie scope ради обхода.
2. **Admission:** cookie→member/session, 18+/current mock-entry acceptance, open room, текущий slot/host/consents/scope и active media lease проверяются при каждом join, validate и reconnect. Проверить JWT подпись/issuer/exp, room/identity/minimal grants и соответствие `identity=непереиспользуемый leaseUUID`; token принадлежит ровно этому room/member/session-generation/scope. Server-refreshed JWT не заменяет DB authority, не оживляет revoked lease и не обходит текущий session fence.
3. **Race fence:** под общим room/lease lock проверить generation и finalAccessFence, зарегистрировать живые proxy sockets до разрешения forwarding, затем финально перепроверить перед открытием. Отзыв сначала durable monotonic lease retirement/ledger, затем server RemoveParticipant и закрытие обеих proxy сторон; pending upgrade/join также отменяются. После late upstream join повторить remove, не оставить гонку «remove до появления участника». Чужой backend-cookie/token, старый nbf/refresh/reconnect/sid не дают доступ.
4. **Lifecycle:** lease никогда не реактивируется, rejoin после нового consent создаёт новый UUID/generation. Room close/leave/18+ reaccept/host-source-ended/lease expiry отзывает необходимые scopes. Restart/restore не поднимают прежние media grants; reconcile SFU rooms/participants до serving. Protected retirement ledger не откатывается вместе с PG backup. Lease watchdog обязан работать при падении API/gateway; lost/corrupt authority — fail-closed, включая активный media.
5. **Namespaces/минимальные grants:** opaque separate cinema room, general call room и pair-session room с собственной generation. Cinema: ровно один host publisher lease с источниками screen_share/screen_share_audio, остальные subscribe-only, без camera/mic/data/admin. Calls: только явно согласованные mic/camera, до8. Pair: ровно два актуально согласованных участника, host основной комнаты не получает moderator/subscribe право. Room/service admin ключ только backend, не клиент. Room name/identity/metadata без display names, отношений и приватного текста.
6. **Границы сервера:** `room.auto_create=false`, create нужных rooms сервером с MaxParticipants8/2; дополнительные bounded track/subscription/bitrate/metadata/room/admission limits. Не включать remote-unmute, recording/egress/ingress/SIP/agent endpoints или экспериментальный `rtc.enable_warp` (в pinned source off by default). PublishSources ограничивает заявленный вид track, не доказывает честность содержимого клиента.
7. **Хост:** отдельный непривилегированный service/process, pinned amd64 digest, cap_drop ALL, no-new-privileges, read-only filesystem, bounded tmpfs/pids/CPU/RAM/log rotation; никакого Docker socket. Один сервер и один хост не требуют Redis для первого standalone single-node профиля; новый Redis не добавлять без измеренной потребности. Конкретные sandbox/сокеты/nonroot/health runtime совместимости ещё проверяются.
8. **Продукт:** host явно вызывает getDisplayMedia по user gesture. Обязательны реальное video+audio наличие и remote receipt; no-audio/denied/ended/protected-content/transport-unavailable показываются честно и безопасно завершают lease. Нельзя выдавать canvas synthetic AV за настоящий browser tab capture. Music pause policy вызывается authoritative Cinema state, не простым local button; Calls используют тот же transport позднее.
9. **Откат:** server capability-off прекращает issuance, retirement всех затронутых leases + подтверждённое SFU removal, затем совместимый возврат API/client/media image. Новая версия не читает старые live grants как active. Старые retirees/18+/room-only TTL не откатываются. P06 backup новые schema/config paths включить до P07.

## Node/browser/codec и сетевой профиль

Published server SDK2.19.2 engines Node>=19 — Node24.22.0 удовлетворяет. SDK ESM exports подходят Venus ESM по source, фактический bundle/type/runtime — будущие targeted checks. Browser SDK build target содержит Chrome64+/Firefox58+/Safari11.1+/Edge79+, но это транспиляционные targets, **не** screen-audio/support матрица Venus. Нужны secure context, browser permissions и реальные возможности capture. Официальный screen-share пример требует browser tab и включённое share audio для соответствующего browser. Реальные Android/iOS не предоставлены; desktop audio capture разных ОС/браузеров пока NOT_RUN. [Screen sharing](https://docs.livekit.io/transport/media/screenshare/), [Node package metadata](https://registry.npmjs.org/livekit-server-sdk/2.19.2).

Для начального normal локального профиля выбрать обычный WebRTC Opus + VP8 и сверить negotiation в runtime; необязательные AV1/VP9/H265 и experimental WARP не добавлять в scope. Codec support и hardware/mobile constraints не считаются принятыми по наличию SDK. SFU не обязан транскодировать/исправлять несовместимые browser captures.

Порты по официальному guide: 7880 TCP API/WS **внутренний**; ICE TCP7881; UDP mux7882 вместо диапазона50000–60000 UDP; optional embedded TURN3478 UDP/TLS5349 (или443 по принятому ingress-профилю), всё тот же host. Для локального Docker выбрать mux + TCP fallback, без внешних STUN/TURN по умолчанию; advertised candidate IP должен реально достигаться browser clients. TURN/TLS/публичные NAT/Cloudflare маршруты не доказываются этим локальным профилем. ICE/media порт не является HTTP signaling bypass, но удаление действующего DTLS требует server removal. [Ports/firewall](https://docs.livekit.io/transport/self-hosting/ports-firewall/).

Поставщик рекомендует host networking ради производительности; здесь сохранение private7880/gateway fence важнее слепого копирования рекомендаций. Bridge+mux требует своих измерений; host network без жёсткого внутреннего bind/firewall откроет bypass. CPU/bandwidth ограничивают SFU; коммерческие benchmarks не доказывают capacity этого хоста. Профиль ресурсов/число media rooms, 1+7 и конкуренция с Games/PG должны быть приняты/измерены до заявления support. Общий soak/load/restore стенда остаётся финальному P07, но targeted 1+7 A/V/revoke/network — обязательны самому P09.

## Независимый entry verdict и следующие проверки

**PASS_FOR_IMPLEMENTATION_WITH_MANDATORY_FENCES**: owner scope, source candidate/pins и архитектурный путь совместимы; внешних ключей/хостов для реализации не требуется. Это условный допуск к разработке после решения оркестратора, не подтверждение отсутствия дефектов и не разрешение публичного запуска. Unfenced native self-host JWT profile — **REJECTED**. Если gateway/supervision невозможно реализовать и подтвердить, выбор пересматривается; более низкоуровневый mediasoup потребовал бы собственного signaling/browser producer-consumer lifecycle и native worker build, поэтому без такого провала не уменьшает объём работ. Mediasoup здесь не аудирован и не принят как эквивалент.

После всех правок P09 — прицельно: all4 endpoint/cookie/Origin/grant negatives; native+refreshed stale JWT replay после revoke/restore; pending join-vs-close race; действующий A/V stops после server remove; crash API/gateway/watchdog/SFU/admin-network-failure; 1publisher+7viewer actual A/V, reconnect, no-audio/denied/ended; normal/throttled/UDP-blocked TCP fallback; Games и фактически включённая Music pause, compatible rollback. ADR009 proposed p95≤120ms A/V, viewer skew≤500ms, glass-to-glass≤2s сохраняются; measurement clocks/warmup/duration/sample count фиксируются до запуска, источник synthetic и настоящий capture разделяются. Большие P03 статистические suites не нужны.

Остаются **HOLD/NOT_RUN**: P09 prototype и весь runtime, dependency closure/image advisories, доступность/нагрузка/capture качество; P07 aggregate load/soak/full restore; P10 реальные устройства; public-network ICE/NAT/TURN/DNS/TLS/Cloudflare/production. P08 exit не принят этим отчётом. Все последующие реализации и приёмки требуют точных свежих bytes и nonauthor exit reviews.

## Журнал ошибок исследования
