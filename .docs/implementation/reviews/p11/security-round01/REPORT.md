## Accepted blockers

**S11-01 — private participation count leaks through Cinema (P2).** `apps/api/src/media.ts:57` counts all room media leases with publisher=false, without Cinema kind/current scope filtering. Default listen-only private-pair leases satisfy that query. A foreign member or host can observe private participation changes through Cinema.viewers even while GET Calls correctly hides pairs. This violates the explicit private-count projection contract. Filter to Cinema kind and current Cinema scope/upstream. Verify an outsider/host observes unchanged Cinema count while a listen-only pair is active.

**S11-02 — failed pair leave retry can falsely confirm both-party cutoff (P2).** `apps/api/src/calls.ts:67–69` and `apps/api/src/media.ts:112–123`. First failed pair retirement marks both leases pending and ends the scope. On member/scope retry, only the caller's pending row is selected; retirementScopes omits the already-ended pair, and wholeScopes is derived from Cinema publishers and returned call scopes rather than selected pair rows. The retry can successfully RemoveParticipant(caller) and return200 while the other peer's cutoff remains pending. Exact lease release follows a different branch and does not fix this Calls.end/retireCallsMember path. Include retained selected pair upstreams in whole-room removal, as the watchdog already does. Relevant check: failed pair leave503, retry200 only after both old grants are denied and the old backend room/participants are gone.

**S11-03 — stale capture intent resumes after asynchronous unpublish (P2).** `apps/web/src/calls-panel.tsx`, source handler. It awaits stopSource before allocating the request generation. A newer device/off intent can occur while the old publication is unpublishing; the old continuation then allocates a newer serial and starts stale getUserMedia, potentially replacing tracked resources. Allocate/invalidate intent before the first await and recheck immediately afterward, retaining later capture/publish/error fences. Device/off input must invalidate an outstanding intent even while stopSource has already made the UI appear muted. Hold old unpublish in the existing browser mechanism, issue a newer device/off intent and assert no stale device activation/publication.

**S11-04 — peer expiry is not carried to the final synchronous pair fence (P2).** `apps/api/src/calls.ts:18–24`, `apps/api/src/media.ts:80–81,135–143`. currentPair checks both sessions/consent by SQL count at a captured time, but retains no peer deadline/fence. Grant/frame/gateway then await more work and finally fence only the caller. The peer session or existing pair lease can expire during that final await, yet the caller closure can still enqueue after the peer deadline. A room lock prevents concurrent mutations, not wall-clock expiry. Carry scope/peer-session/existing-peer-lease deadlines into a synchronous scope fence invoked after the final awaited caller fence; preserve listen-only and consented-but-not-yet-granted peer semantics. Use the existing controlled-clock/final-boundary mechanism to cross peer expiry and assert no grant/frame enqueue or upstream activation.
