[Android command-line builds](https://developer.android.com/build/building-cmdline) support Windows/Linux; [APK signing](https://developer.android.com/studio/publish/app-signing) distinguishes debug and release. This makes Android code/build preparation feasible without pretending a signed production release exists. Existing repository inspection found no Android/iOS native project among tracked-path name matches; no compiler/emulator/device probing was performed.

Android playback capture begins at API29 and requires approved MediaProjection, RECORD_AUDIO permission, same user profile and permitted source usage/policy. MediaProjection has per-session system consent and Android14+ foreground-service/one-use requirements. A permission named RECORD_AUDIO must not silently become microphone capture. Stop/revocation must release actual capture, not leave a black/silent stream called live AV. See [projection lifecycle](https://developer.android.com/media/grow/media-projection) and [permitted audio capture](https://developer.android.com/media/platform/av-capture).

Current Apple documentation introduces an availability-dependent route: [iOS ScreenCaptureKit sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-on-ios) requires iOS27+ and marks preliminary technology. It cannot be generalized to older devices. [ReplayKit](https://developer.apple.com/documentation/replaykit) remains the older capture/broadcast reference with source restrictions; it is not a promise all app audio is available. Official upstream [LiveKit Swift main guide](https://github.com/livekit/client-sdk-swift/blob/main/Docs/ios-screen-sharing.md) distinguishes iOS27+ ScreenCaptureKit, system-wide broadcast extension/AppGroup and in-app-only capture without app audio. These moving documents are discovery, not an approved native SDK pin. Choose an OS floor from actual device targets and audit that exact released SDK; do not silently replace older-device support with the newest API or claim compatibility from a main-branch page.

[Xcode support](https://developer.apple.com/xcode/system-requirements) requires matching macOS. [Distribution methods](https://help.apple.com/xcode/mac/current/en.lproj/dev31de635e5.html), [account provisioning](https://developer.apple.com/help/account/basics/about-your-developer-account) and [AppGroup configuration](https://developer.apple.com/documentation/Xcode/configuring-app-groups) must be verified for the chosen route.
