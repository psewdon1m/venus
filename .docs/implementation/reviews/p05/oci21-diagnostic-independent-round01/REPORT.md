## Diagnostic correctness, privacy, and bounds

The two wrappers synchronously persist a checkpoint before invoking the real host-context-close and observer-page operation. Each uses one immediately unreferenced 1000 ms interval only across that operation's pending await; finally clears it. The original operation is still awaited. A failed write latches failure and stops the interval, then prevents successful return when the operation settles; it does not cancel a stalled native promise. The unchanged host phase/whole limits remain necessary.

One exclusively created ResourceLease output file is rewritten through its own O_WRONLY|O_NOFOLLOW descriptor. Every record is exactly 4096 bytes with whitespace padding, at offset zero, with a complete-write assertion; subsequent writes recheck lease and output reserve. No append or per-sample file is created. Sample count is capped at 1000. The descriptor closes before context/runtime cleanup; a close failure makes cleanup fail rather than restore success. At sample/write failure the previous file can remain, so consumers must treat it as a diagnostic observation, never an acceptance oracle or guaranteed latest state.

Resource reads use only four fixed Linux cgroup paths and /tmp statfs. Only pids.current, pids.events.max, memory.current, memory.events.oom/oom_kill, and total/available tmp bytes are projected. Values must be nonnegative safe integers; unsupported, absent, malformed, negative, and unsafe observations become explicit null with unknown:true. No read error string is exported. Existing gate diagnostic values are bounded and only the first four gates are included with overflow flagged. The 37 static diagnostic steps exactly match the parent browser's pre-existing literal steps. No ENV, credentials, cookies, API/private DTO, DOM, title, heap, arbitrary path, raw error message or stack is emitted. The unchanged safeError helper emits only whitelisted class/code/phase and validated module/line/column fields.

Caught failure is written before context cleanup and cannot override report FAIL. Existing terminal reporting remains after cleanup. A checkpoint with state AWAITING proves only the last recorded before/pending-await observation. It does not prove the operation was still pending when a later export occurred: after that await resolves, the file can remain while subsequent work proceeds. Absence, a stale checkpoint, unknown resource readings, or last-sampled counts cannot establish an OOM, pid, tmp-space, API, or Playwright cause. Sampling also depends on the JavaScript event loop and successful export; it is not an independent watchdog or liveness remedy.

The unchanged host-runner/profile bytes retain original 14 acceptance oracles, 120000 ms phase and 900000 ms whole bounds, traffic/clock/fixture/consent/equality checks and quotas. Browser configuration remains 1536 MiB RAM, 128 pids, /tmp 16 MiB. The separate 512 MiB artifact/storage cap is not browser RAM. No resource bound was raised.
