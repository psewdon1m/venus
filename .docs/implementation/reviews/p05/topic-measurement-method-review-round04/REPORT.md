## Concrete P2: P05-METHOD04-001

**Keep actual host-space guards active during stopped-prefix export/archive, and guard host writes.** In frozen `r100-v3-watchdog.mjs` lines 59–70, the failure path writes one stop guard and enters its post-stop loop. That loop checks owner, heartbeat, phase deadlines and DONE flags, but never calls `statfsSync` again or refreshes actual available bytes. The launcher can then continue export and archive. Frozen `r100-v3-package.py` lines 53–60 and 80–83 write extracted files or the archive without checking actual host free space before writing. Their `check()` verifies allocated/logical partition bytes, which does not replace the free-space reserve. The launcher has phase-boundary `footprint()` checks (lines 37, 47–48), but not every host write or continuous failed-prefix monitoring.

This contradicts the frozen proposal's explicit reserve+remaining-cap requirement before each phase/write and its active post-failure supervisor policy. A RUN timeout and a later external C: space loss can coincide. The result correctly remains NOT_ACCEPTED; the defect is continued unguarded host output, not a false statistical PASS.

[Exact-function inert replay](watchdog-inert-replay.mjs) takes the frozen `nextPhase`/`supervise` function bodies, removing only the module `export` modifier, and substitutes clocks, files and Docker replies. BOOTSTRAP → PROBE → RUN times out; available host space then becomes zero. The launcher model advances EXPORT → ARCHIVE → CLEANUP → DONE. [Observed result](watchdog-inert-replay-result.json): four statfs calls before stop, **zero after stop**, stale guard still reports 12 GiB, and the supervisor records `FAILURE_PREFIX_EXPORTED_AND_CLEANED`. No actual Docker or measurement operation occurs in this replay. It establishes a control-flow gap, not an actual disk-full event.

Required correction: maintain independent actual host-space sampling and bounded stopping throughout failure export/archive/cleanup. Gate host tar staging, extraction chunks and final archive writes on a fresh owner/counter guard plus actual free-space/reservation checks. On low, unknown, stale or reordered data, stop allocating further output, retain the exact owned prefix/volume and report NOT_ACCEPTED/manual cleanup as applicable. Reserve prospective allocation or conservatively bounded metadata before writes, then recheck the partition/global equation. Add finite tests with space loss during extraction and archive, as well as post-timeout export; preserve the old FAIL and this review. Review fresh bytes before preparation or root execution ACK.
