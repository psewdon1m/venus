## Operational layout proposed for independent review

1. Readonly input snapshot lives outside the owned output directory. Before execution hash every producer/source/compiled input and calculate its complete size once. Mount it readonly; bind identity/source/compiled maps to the new root image and retain exact pre/post equality. Input bytes remain accounted separately; they do not become zero-cost or unpinned.
2. Use one unique labelled Docker volume for Linux-native owned output. No unrelated volume/path, including R:, may be used. Before creating it verify actual C host free >=10GiB plus the entire bounded diagnostic output/export upper bound. During execution retain the actual C guard heartbeat and volume statfs checks; inspect the backing disk assumption explicitly. If either guard is unavailable/stale/low, stop NOT_ACCEPTED.
3. Keep gzip6 and lossless NDJSON. Final production chunks remain <=4MiB. Avoid the diagnostic-only terminal-round flush for full runs: preserve raw records in bounded chunk buffers and write progress every10s or fixed chunk boundary. A hardkill loses an explicitly unaccepted pending prefix; it does not make a completed section. Never remove required raw fields/records to fit disk.
4. Accepted resource v2 recursively counts the existing tree at every write. With inputs in that tree, every output write re-enumerates unrelated immutable inputs. Moving inputs out is a method change with new source pins, not proof that this was the measured bottleneck. Linux volume tests and per-layer timers must establish the contribution. Large final output trees may still make full rescans too costly; any ledger/incremental accounting writer requires its own new independent review with junction/ADS/path/limit/disk and unexpected-file controls. No concurrent hostile-filesystem race guarantee is claimed.
5. Export once into a fresh owned host staging path after stopping the worker. Check remaining space for native+export+archive coexistence before every copy, validate every chunk digest and raw count, then atomically publish a completed manifest. Do not delete the native volume until export verification succeeds, except at a separately authorized terminal cleanup policy. On failed export retain NOT_ACCEPTED evidence within declared budgets and record its owned volume; never hide a cleanup failure. Diagnostic output20MiB and final32GiB include retained output plus temporary duplicate export/archive bytes unless root explicitly accepts a different conservative bound. Current C free≈27.6GB does not establish that32GiB fits.
