## Поведение и отрицательные границы

Новый snapshot получает private_text_chat только при операторском flag===true, в обоих контекстах. Shared privateTransportAvailable больше не имеет очного bypass: private требует включённый backend и frozen capability. chatAvailable дополнительно требует точного совпадения действительного room context и snapshot context. Отключённый/отсутствующий flag, capless snapshot, неподдерживаемый context и несовпадение контекстов не открывают канал. Включение backend не дополняет старый immutable snapshot.

Actual compiled guard bodies отдельно сверены по TypeScript AST tokens с exact source, затем выполнены **98 независимых truth-table assertions**: оба контекста, true/false/omitted flag, present/absent capability, public/private interaction, совпадающий/чужой/unknown room context; unknown snapshot context и capless old IP snapshot также отвергнуты без изменения объекта. Эти controls исполняют реальные методы класса, но не обращаются к SQL и не доказывают транспортную эксплуатацию.

В API изменены ровно4 тела методов: privateTransportAvailable/chatAvailable/draftSnapshot/start. Остальные91 тела, включая newRound, chatFence, replay/receipt/HTTP/WS dispatch, reconcile, selected presence/finalAuth, bootGate/prior и quota mutation пути — побайтно прежние. newRound уже содержал pre-write guard и post-write parent fence: наследуемая защита теперь вызывает усиленный shared guard. Parent fence не потерян. Тесты подтверждают late flag-off после записи и перед выдачей. Host не получает права автоматически: допускаются только настоящие два актёра, в том числе host, если он сам актёр; посторонний host/observer не становится актёром от роли.

Изменение не снимает invitation/topic bilateral consent, epoch/conversation/scope/boot/revision/source/preferences/presence checks, неизменные expiry/clock floors и финальную проверку после credential await. Flag-off reconcile прекращает раунд и очищает private state; повторное включение не воскрешает прежний grant/epoch. Exact retry проходит прежний read-only replay fence, не расходует новую quota и не превращается в обход после отказа. Публичный outbox/схема сообщения не расширены.

В planner изменено только тело options: capless V2 snapshot не создаёт private options до preflight/Start/advance. Публичный безопасный путь остаётся. Остальные30 тел и Random/выбор/recovery/selectNext/replacement функции точны прежним байтам; алгоритм RE-1.P05-TOPIC-2, recovery35%, веса/seed и baseline cap не снижены. ROOM-TOPIC-2 явно отделяет новые входы от прежнего поведения. Старый ROOM-TOPIC-1 snapshot не переинтерпретируется: существующая immutable validation отвергает его; bootGate отзывает transient private objects и безопасно aborts неподдерживаемую активную сессию, сохраняя snapshot/history. Ошибка чтения несовместимого started prior распространяется, а не заменяется пустой историей. Такая старая комната может потребовать новую комнату; это явная совместимость ADR, не тайная миграция/обнуление исключений.

External topic-runtime ledger policy digest, legacy engine.ts/games.ts, private preference/ledger ядро, room/topic routes, private conversation kernel и quota policy —9 явно проверенных зависимостей — побайтно совпадают с прежним source1274. Лимиты12/минуту,128/раунд,32-buffer, Unicode/UTF8 bounds не менялись. P03/старые V1 доказательства этим не переименованы в V2.

UI удаляет только online-only условия чтения и показа прежнего pair chat, добавляет корректную метку контекста. В обоих форматах остаются same-identity/transport generation, coherent batch/scope/revision/lease, точный conversation_id/epoch POST, recipient-only private view, clearing при disconnect/expiry/pagehide, Stop/withdrawal и отсутствие fallback в room chat. Поле ввода зависит от свежего conversation permission; capability нельзя выдать изменением UI. Компонентные сценарии проверяют очное чтение/показ, send через тот же V2 путь и удаление приватного UI при transport loss.
