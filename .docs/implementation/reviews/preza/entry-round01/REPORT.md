## Minimal Venus contract

### Authority and exposure

Use room-prefixed routes matching existing cookie paths: `/api/v1/rooms/{room_id}/presentations/...` (a separately declared V2 equivalent only if actually needed). Current room session, member admission and current offer/18+ acceptance authorize every library/state/PNG/job read and control; UUIDs, titles, slugs and URLs are not credentials. Only current room host may import, replace, configure, delete, start/stop live or change the shared page. Room members may view the room's library/current presentation. No anonymous public preview, independent viewer password, share link, operator credential or privileged Docker capability enters this API. Mutations retain exact Origin, CSRF, bounded parsing, per-member/room rates, request identity and idempotency/body-conflict rules. Reads reuse the existing browser/room delivery fences without bypassing reacceptance or protected retirement. Safety leave/close stays available independently of presentation errors.

Minimal operations: list/get library/state; host import PDF; get own authorized job status; host update title/default_mode(scroll|slides)/allow_switch; host replace source; host delete; host live start(page)/set-page/stop; member get current-version PNG. State includes server presentation ID, room ID, presentation revision, opaque immutable content_version, page count/dimensions, settings and live/current-page state. Job state is pending/running/ready/failed/cancelled with sanitized code and bounded progress, not file paths or PDF parser output. API shape, error codes, bounds and privacy projections must be a new contract revision before implementation is frozen. Do not rewrite historical P00 schemas or accepted traceability/proofs.

All mutating control commands bind expected revision and current content version, plus request ID/idempotency. New content resets current-page to the first page and stops live, as Preza does. Use one documented indexing convention (recommended zero-based wire index, one-based UI label); validate it against the actual page count. Distinct presentation and room revisions must not overwrite each other. A room may have a single selected live presentation in this minimal shared-stage integration; any different concurrency policy must be explicit before enabling. Host preview remains host-only and may browse other pages. While room live is active, the ordinary member PNG route authorizes **only the current presentation, exact active version and current page**; wrong current page gives 409 without bytes, unknown/inaccessible/stale content gives a sanitized inaccessible result. Raw source PDF is not served to viewers: that would bypass the slide restriction.

### Data, atomicity and races

Prefer additive PostgreSQL tables with composite room/document/version/page ownership FKs, unique IDs, byte/page/count checks, job-generation and request-key uniqueness. Metadata and bounded PDF/PNG bytea objects belong to the room lifecycle and pg_dump. Store room-private document bytes encrypted at rest under a separately versioned binary/blob envelope using the existing key authority and scoped AAD (room/document/version/kind/page), not the small padded preferences JSON API; keys never enter converter or backup. Binary-envelope overhead counts toward quota. This is server-readable encryption, not E2EE.

The API reserves worst-case upload/output quota atomically before accepting work; the active old version plus pending PDF/output and reservations all count, across every room and globally. Do not double-credit free space until durable deletion/cleanup completes. A room maximum is a ceiling, not a promise that global capacity is available. The job gets server-generated identity, nonce and current room/host/content generation; user names never form paths.

Do not hold a room/DB lock while Poppler runs. Keep the previous ready version usable during staging. A converter receives only bounded input bytes and an opaque job correlation ID; result metadata is untrusted and independently checked for count, PNG signature/dimensions, digests and cumulative bytes. Publish only a complete verified result in one transaction after reacquiring the existing room ordering/lock and current host admission/acceptance, serving and protected lifecycle fences. CAS against the captured document/content revision and current job generation; stale jobs, close, idle expiry, host/member retirement, delete, replacement, maintenance or feature disable prevent publication and trigger cleanup. Never let an old completion recreate a deleted room/document or supersede a newer replacement. On conflict/error/crash, old ready pointer remains unchanged and reservation/scratch recovery is idempotent. Document replacement/deletion retire the old version and invalidate old URLs; no half-converted version is visible.

At PNG/state/event enqueue, repeat room/member/entry/serving and presentation/current-version/live-page checks after all awaits. For PNG the bounded page can be buffered, then synchronously enqueued under the same linearization/final-fence discipline as current private delivery; do not insert unfenced serializers/onSend work after authorization. Bound per-client pending bytes/requests, abort queued work on revocation and never log document bytes/title/text, temporary paths or credentials. Already authorized and delivered/queued bytes cannot be recalled from a recipient; the guarantee is denial of new unauthorized delivery, not erasure of screenshots or prior offline copies.

### Conversion envelope — proposal to implement, not measured capacity

Keep proposed hard ceilings: source **16 MiB**, **100 pages**, fixed **120 DPI**, PNG **4 MiB/page**, **64 MiB/document total**, room stored+staging+reserved ceiling **128 MiB**. Reuse the actual Python/Poppler implementation with guard/wrapper changes; retain the PDF signature plus successful pdfinfo checks and reject unreadable/encrypted inputs. No shell interpolation, URL/callback import, user-selected DPI/command/path or archive extraction.

Add concrete conservative initial ceilings to the implementation contract: positive finite dimensions; rendered width and height each <=8192 pixels and product <=8,000,000 pixels/page; at most one running conversion globally, one pending job per room and at most two pending metadata-only jobs globally; CPU 1 core, memory 512 MiB, pids 32; combined scratch/spool tmpfs <=128 MiB; RLIMIT_NOFILE 64, core dumps disabled, per-file RLIMIT_FSIZE <=16 MiB plus a stricter PNG 4 MiB watcher; total metadata subprocess wall time <=30 s, complete job wall time <=120 s including metadata, worker child-process CPU budget <=90 s with a whole-job watchdog. Oversize/timeout yields a normal sanitized failure and preserves old content. Pending jobs do not store unbounded request bodies in memory. Render/check incrementally so the 64 MiB aggregate and 4 MiB/page are enforced during work; tmpfs/memory/process limits remain the hard stop even if a parser misbehaves. Capture parser output only through bounded buffers (e.g. 256 KiB combined); no raw stdout/stderr to consumer/log. These numbers may reject complex valid PDFs; do not claim arbitrary PDF compatibility or throughput. Change them only as a new bounded source/config revision, never by silently removing a limit.

Converter image is separately digest-pinned with explicit Python/Poppler dependency provenance and reproducible package pins. It runs as a distinct nonroot UID (not the privileged operator/executor UID), read-only root, cap_drop ALL, no-new-privileges, no Docker socket/host files/secrets/keyring/DB/admin credentials, and no exposed host port. Preferred minimal isolation: `network_mode: none` and a dedicated bounded ephemeral spool with narrowly scoped permissions accessible only to API and converter. Static Compose/supervision owns worker lifecycle; the API gets no Docker socket to launch jobs. No converter connection to DB/API/metadata services or arbitrary network. The spool must not share protected ledgers, app source, backups or secret mounts. API validates server-owned job paths, regular single-link files, no symlinks/traversal and bounded output; converter filenames/manifest cannot choose a read/write target. If a different IPC is selected, specify equivalent network/egress and identity isolation before enabling rather than calling a generic internal bridge sufficient. Purge scratch after each job and startup/recovery; errors/kill/room retirement clean pending work. Budget converter and raster UI load alongside same-host media; local P07 measures actual combined capacity.

### Viewing, sync and reconnect

Preserve default scroll/slides and host allow_switch. Outside live, member mode/page is local session state, keyed by room+member+document+content version; it never mutates shared page. During live, effective mode is slides and current index is server-owned; local browsing/prefetch of other pages is disabled **and denied server-side**. Restoring a locally saved mode cannot bypass live. On stop, restore the permitted local/default mode, not a phantom live state. A failed or stale page load refreshes scoped state rather than trying arbitrary pages.

Use existing room WS/ticket/generation fencing or an equivalently authenticated room-scoped snapshot stream; preserve Preza's current-state-on-connect behavior without deploying its public SSE. Snapshot includes active document/version/settings/revision/live/page, not source bytes or private pair data. Late join first authenticates/accepts, then receives a full current snapshot and fetches only the current allowed image; it must not replay page 0 merely because that was the original start. Ignore older revisions and superseded room/member/socket/content generations. Reconnect fetches fresh state, never auto-restarts live or renews retirement. On disconnect mark stale and disable host control until authoritative state returns; on permission/room/identity change clear rendered images, object URLs, local scoped state and pending requests. Use no-store/no public CDN/service-worker/image cache for private assets; no unauthenticated 304/Range shortcut. Support RU/EN/TR labels, existing keyboard/reflow/reduced-motion rules and aspect-ratio containment. No animation behavior beyond the original static viewer is implied.

### Retention, restore and rollback

Idle expiry remains 24 h; close immediately revokes reads/events/jobs/live, primary room data is purged no later than current 23 h implementation horizon (within owner <=24 h), backup lifetime <=7 days. Scratch cleanup is immediate/bounded retry and never waits for primary TTL. Member leave/revoke removes that member's access but does not delete the shared room library for everyone. Do not attach presentation authority to the private pair chat epoch or alter ADR-025 functionality.

PG bytea simplifies backup inclusion only. **Mandatory minimal storage remedy:** pin a global presentation budget (e.g. initial 64 MiB including ciphertext/staging/reservations) and serialize global quota changes; reserve baseline DB/WAL/free-space headroom using current measured size and conservative accounting. `pg_database_size` alone does not prove pg_dump size: relations/indexes/WAL, bytea encoding and compression differ. To retain MAX_DUMP=128 MiB, a demonstrated bounded dump margin over the accepted whole-DB fixture plus admission cutoff is required; if it cannot be guaranteed, use the preferred explicit bounded P06 envelope expansion (e.g. 256 MiB) consistently across producer, temporary/archive file, header/read limits and restore validation, with fixed global/room budgets and disk reserve. It is not permissible simply to remove MAX_DUMP. Existing readBackup requires schema generation 1; release/schema compatibility must explicitly account for additive presentation migrations instead of widening verification blindly. Quotas include duplicate active/pending bytes; reserve disk for WAL/temp/backup and fail admission before jeopardizing Rooms.

Add converter/job quiescence and an epoch fence to the existing operator serving-close/stop/backup boundary; today driver.stop() checks only app. A converter may continue CPU work only if it cannot commit or leave reusable completion after the epoch changes; clean/cancel its spool before restore/serving. Keep protected room/member/deletion and new document retirement/version floors outside the rollback unit. Before admission after restore: migrate compatibly, verify keys and protected witnesses, reconcile room/member/doc retirement and expired jobs, discard stale staging, reset live to stopped, then allow explicit new host start. Missing required keys/authority keeps serving closed. Demonstrate intact PDF/PNG/library/settings restoration for nonretired data and denial of restored deleted/replaced data. A DB file alone is not clean-host recovery of protected metadata/keys.

Rollback first disables presentation admission/delivery/control and cancels/fences jobs. Preserve room exit and existing games/music/media/private chat. Additive tables can remain unread by a compatible previous app; do not run destructive down migrations or automatically restore an old DB on ordinary restart. An incompatible image/schema requires the existing P06 closed-serving recovery path with protected floors preserved, not a blind image downgrade. Never overwrite released tag/assets, accepted proofs or source snapshots. A disabled feature does not make its stored data exempt from retention/backup.
