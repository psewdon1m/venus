## Cause and scope

The assertion crosses a process boundary without excluding legitimate writers. privateFixture creates live sockets; room-routes.ts:200–206 polls every1000ms using Rooms.socketState. Rooms.socketState (rooms.ts:395–405) takes the room row lock, then Games.socketView (games.ts:506–507) locks the game and calls reconcile. reconcile (131–141) observes expiry, saves the changed round, and bump (101–103) increments game_sessions.rev. Maintenance also reaches memberStateChanged/reconcile (rooms.ts:435–468; games.ts:477–480), although its10000ms interval and retained logs do not prove it was the particular writer. A1-second socket poll is consistent with both failures. There is no per-transaction trace identifying the precise writer, and this report does not invent one.

The shared catalog advisory lock746826405 serializes against catalog changes, not other shared-holder room/game mutations. The old test sets a file clock shared by the test and serving child, permitting a writer to commit the expiry before the final stored-revision query. Restoring the clock cannot undo that committed revision. This failure does not demonstrate publicDelivery wrote: that call ran in a PostgreSQL READ ONLY transaction and passed, while the failing assertion occurred afterward.

## Minimal safe stabilization

Use a separate read-write gate transaction: BEGIN, shared catalog lock746826405, then SELECT the target rooms row FOR UPDATE (or existing operator.rooms.lockRoom(gate,r.id)). Acquire it BEFORE reading/decrypting the baseline round/revision and BEFORE moving the shared clock. Holding only hashtextextended('venus:room:'+id,17) advisory lock is insufficient here: tests/p04/server.mjs:18 and runtime.integration.test.mjs:28 do not enable privateProtocol, and Rooms.room (106–108) calls roomOrdering only when that option is enabled. The row lock is the common V1 writer fence.

Keep the actual publicDelivery invocation on its separate BEGIN READ ONLY client, with the existing shared catalog lock and unchanged current_round/game_rev assertions. Query and assert stored rev unchanged WHILE the gate row lock is held. Do not await HTTP/WS/maintenance completion while holding the gate.
