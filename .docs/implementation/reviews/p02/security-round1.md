## Findings

| ID | Priority | Finding and reproduction | Required closure |
| --- | --- | --- | --- |
| SEC-01 | P1 | `apps/web/src/main.tsx`: an existing mounted room hides the entry-policy branch. On an offer change, an authenticated non-safety mutation receives `ENTRY_REACCEPT_REQUIRED`; `perform()` resets acceptance and refreshes policy but `room && prefs` still selects RoomShell, so the acceptance checkboxes and `reaccept-room` button are absent. | Show the current version and unchecked acceptance controls within the mounted room and verify recovery without page reload in a browser. |
| SEC-02 | P2 | `apps/web/src/room-shell.tsx`: `savedRev`, comfort and edges are initialized from props once. An external preference mutation or peer leave can advance the server preference revision. Save then conflicts; the error retry calls `refresh()` but does not advance the mounted form's `savedRev`, so subsequent saves keep conflicting. | Reconcile the form with authoritative preferences and verify stale write → explicit refresh/reconciliation → successful subsequent save. |
| SEC-03 | P2 | `apps/api/src/rooms.ts`: maintenance marks an online member reconnecting at the presence timeout. A subsequent ping on the same valid socket updates timestamps but never restores `presence='online'`; the member can remain reconnecting while sending heartbeats. | Restore online presence and emit a revision when a valid heartbeat recovers presence, or document and prove another recovery mechanism. |
| SEC-04 | P2 | Entry review requires transactionally recorded mutation audit metadata and persistent count/age/bytes bounds. The reviewed migration contains no audit table, `emit()` stores only a RoomView in outbox, creation/reacceptance omit such metadata, and outbox cleanup provides an age limit without count/bytes limits. | Provide the scoped minimal mutation audit with bounded storage, or an explicit normative applicability resolution proving the requirement is legitimately deferred. Do not claim the current outbox is a complete mutation audit. |
| SEC-05 | P1 | `rooms.remember()` stores `SHA256(canonical(input))` as a plaintext request fingerprint for preference writes. An observer of the database/backup knows the idempotency UUID, room/member IDs and can enumerate the small comfort/relation domain. A targeted reviewer execution against the built `security.js` recovered comfort 4 and relation crush uniquely in 30 guesses for a two-member room. This defeats the intended database confidentiality even though the preference payload is encrypted. | Use an externally keyed, domain-separated and versioned fingerprint or encrypt the original canonical request. Verify existing fingerprints across supported key rotation; test replay/conflict and that unkeyed database-only enumeration cannot reproduce the stored verifier. A public salt alone does not prevent guessing. |
| SEC-06 | P1 | AES-GCM currently preserves plaintext length. For one edge in a two-member room, decoded ciphertext bytes uniquely identify each relation: just_met 102, friendship 104, crush 99, situationship 107, in_relationships 110, not_a_friend 106. This was executed independently with a synthetic key against the built `security.js`; no real key or private data was read. The database observer can infer the relation without decryption. | Pad private preference payloads to a fixed bounded envelope; cover private preference mutation replies in encrypted idempotency storage as well, otherwise the second cipher remains an oracle. Test equal ciphertext size across all six relation values, comfort values and supported edge counts. |

## Preliminary positive observations

Admission serializes on room rows and has a unique room/slot constraint. Session validity is checked again after acquiring the room lock. Host privilege depends on the current host member ID, not names or invite possession. CSRF and strict Origin checks cover cookie mutations. Room cookies are path scoped and duplicate credentials are rejected. WS tickets are consumed atomically and tied to room/member/session; generation checks fence old sockets. Private preferences use AES-256-GCM and room/member/schema AAD; safe room projections omit comfort and graph edges. Production entry is fail-closed while no approved offer exists. Closing writes an external durable revocation before database changes and startup reapplies it before listening.

These observations do not constitute EXIT-P02 acceptance. Final review must bind an exact committed source SHA and inventory identity, assess the fixed findings, and inspect current test evidence.
