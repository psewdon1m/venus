# Обработка полной рецензии P04: промежуточный draft r2

Это **новый черновой кандидат**, подготовленный по предоставленной владельцем полной рецензии от 2026-10-19. Исходные 450 файлов r1 сохранены без изменения. Общий вердикт рецензии — **HOLD**; этот пакет не превращает его в разрешение выпуска.

## Что обработано

Все 450 персональных строк связаны с исходным ID, ревизией, raw/canonical SHA256, строкой рецензии, решением, приоритетом, осями, замечанием и выполненным действием в `dispositions.json`.

| Исходное решение | Количество | Обработка |
|---|---:|---|
| KEEP | 162 | 108 Q/TD сохранены побайтно; 54 YB получили только обязательное общее уточнение права P1 и взаимного подтверждения. |
| EDIT | 120 | Подготовлены конкретные исправления RU/EN/TR с сохранением идеи; проверка новой редакции ожидается. |
| RECONTEXT | 29 | 24 нейтральные приватные карточки переведены в публичную пару S1/C0; 4 задания получили письменную альтернативу, ещё 1 публичная YB — явный добровольный выбор в тексте. |
| MOVE_TO_RULES | 71 | Исключены из случайного кандидата; привязаны к 19 конкретным требованиям UX с проверочными сценариями. Интерфейс здесь не реализован. |
| REPLACE | 67 | Старый смысл явно выведен из этой редакции; новый сюжет записан под стабильным ID с revision 2 и ожидает новой проверки. |
| HOLD | 1 | YB-1148 переписана, но помещена в `quarantine/`; в случайном кандидате отсутствует. |

В `cards/` находятся **378 draft**, в `quarantine/` — **1 draft HOLD**. Это неполный каталог для дальнейшего пополнения: Q 127, TD 127, YB 124. Всего 271 существующий ID получил r2, 108 остались точными r1; 71 удалён из кандидата, но сохранён в истории.

Новые карточки взамен удалённых MOVE_TO_RULES должны получать **новые зарезервированные ID**; возвращать удалённый ID с новым игровым смыслом как KEEP нельзя. Отдельный полный кандидат собирается оркестратором в другом каталоге.

## Приоритетные исправления

- **YB-1111:** турецкое коллективное вето заменено индивидуальным: `Her biriniz hoşunuza gitmeyen bir ifadeyi, gerekçe göstermeden çıkarabilirsiniz.` Любой вправе убрать неприятную лично ему формулировку независимо от другого.
- **YB-1148:** три локали описывают только добровольную договорённость. Явно указано, что она не является технической защитой от снимков экрана или пересказа. Карточка остаётся в карантине до проверки.
- Во всех оставшихся 125 YB, включая карантин, ответ допускает свободное решение P1 после нового условия, явное подтверждение обоих и право каждого передумать. Текст не заменяет серверный автомат согласия.
- Устные/жестовые TD-1001, TD-1009, TD-1011 и YB-1009 допускают равноправный письменный ответ. Исправлены указанные языковые ошибки и разложенный `i` + U+0307 в выдаваемом кандидате.

## Метаданные, правила и семантика

`min_progression_stage` остаётся минимальным порогом существующего движка. Приватные карточки не понижаются ниже S3. Нейтральные рекомендации RECONTEXT реализованы публичной парой с bilateral/acquaintance/S1/C0, без обещания личного канала и без чтения приватных отношений для публичного объяснения. Предварительный тихий opt-in публичного адресата — отдельное требование приложения, не выполненное сменой JSON.

`rules-extraction.json` сохраняет каждую из 71 исходных карточек и связывает её с конкретными требованиями `product-ux-requirements.json`. `global-review-requirements.json` отдельно фиксирует контекст, направленные отношения, глобальный комфорт, канал, повторное согласие, доступность и прогрессию из общих разделов рецензии.

`semantic-clusters.json` содержит 21 явную смысловую группу; `required-scenarios.json` — все V01–V15. Все они требуют дальнейшей реализации/проверки. Нулевой результат лексического поиска не доказывает смысловую уникальность или работающее разведение выдачи.

## Трассируемость и откат

В `revision-diffs.json` находятся покомпонентные before/after изменения всех 271 карточек. Оригиналы остаются в `../p04/cards/`. Пользовательская рецензия и первичный каталог связаны в доказательствах SHA256; digest r1 — `08b327efd3071608ec14b21de6ebeaf91793f61d43c1a71968921967944ba306`.

Оригинальная `.artifacts/p04-authoring-v2.sqlite` открыта только для чтения и резервного копирования SQLite. Её hash до и после совпадает. В доказательствах сохранены неизменённый snapshot, его receipt, начальный экспорт и отдельные попытки authoring replay. Использован существующий `AuthoringLedger.revise` с CAS старого request hash, затем `record`; сохранены обе ревизии карточек и цепочка событий.

Удалённые из кандидата карточки остаются в историческом ledger. **Историческая таблица revisions не является разрешённым случайным пулом.** Только явная карта кандидата выбирает 378 активных draft, а quarantine исключается. Runtime registry и approved pack не изменялись; откат обработки заключается в выборе прежнего входа, а не в потере истории.

## Воспроизведение и ограничения

Из корня проекта:

```powershell
.venv\Scripts\python.exe .docs/content/p04-r2/build_text_overrides.py
.venv\Scripts\python.exe .docs/content/p04-r2/process_review.py
.venv\Scripts\python.exe .docs/content/p04-r2/test_processed_review.py
node .docs/content/p04-r2/replay_authoring.mjs run-03
```

Для replay нужен сохранённый snapshot; номер попытки должен быть новым, существующая папка не перезаписывается. Инструмент воспроизведения пишет только свою копию ledger. После передачи frozen-input другому автору не регенерировать карточки без новой фиксации и уведомления оркестратора.

Проверены схема 379/379, исходные 450 hashes, точное покрытие решений, ревизии, исключение MOVE/HOLD, P0, Unicode, приватные ограничения и карта сценариев. Выполнен настоящий анализ существующим каталоговым движком: загрузка draft и отсутствие точных дублей проходят. **Категорийный лимит 20% и приватное покрытие неполного кандидата ещё не закрыты**; соответствующие пробелы не скрыты и должны быть исправлены пополнением полного набора.

Это не лингвистическая сертификация, доказательство прав/оригинальности, прогон V01–V15 в приложении, новый измерительный M3-прогон или одобрение выпуска. Новые тексты и хеши требуют проверки; статус всех карточек — draft, `reviewed_by/reviewed_at` — null, `rights_status` — needs_review.
